## Summary

- The papers split into two families. **RL-trained learners** (RL², PEARL,
  MELD, TrMRL, AMAGO, ECET) meta-train a memory-based policy with an outer RL
  algorithm across trials of the same hidden task. **Supervised learners**
  (Algorithm Distillation, Vintix, VLRLA) clone *learning histories*
  generated by another improving process. DPT and Vintix II instead predict
  task-specific expert actions from potentially suboptimal interaction
  contexts; those contexts need not be ordered by improvement. Neither
  supervised route requires an already-trained in-context recurrent teacher.
- Every method uses the same interface: each step feeds back the
  previous action, the reward and an episode-boundary flag, and memory persists
  across episode boundaries within a trial. This is what a persistent CTM
  already does, minus the reward and boundary channels.
- Reward is almost always the native task reward. Manipulation work uses
  sparse success: MELD on the real robot, AMAGO's goal relabeling, VLRLA's
  latched success and binary hindsight relabels. No paper here uses a learned
  or VLM reward model.
- Evaluation is in-context improvement: return or success as a function of
  episodes (shots) in the trial with weights frozen, on held-out task
  parameters or held-out tasks. Strong papers add a no-memory or reset control
  and a source-algorithm or oracle reference.
- Held-out *task* generalization stays weak everywhere: about 0.35 to 0.4 on
  Meta-World ML10/ML45 for ECET, and mixed or random on new tasks for Vintix.
  Parametric variation within the training distribution is where all methods
  work.
- For CTM on robots, the most practical path follows VLRLA and Vintix:
  a frozen VLM/motor and trainable recurrent memory reading native features.
  Supervised adaptation pretraining is optional: AD-style histories or
  DPT-style task-specific action labels require appropriate data. Direct
  reinforcement pretraining of the new memory is also a valid route.
  A zero-initialized residual preserves the motor; it does not by itself
  pretrain the memory. See the warm-start clarification below before using
  the historical implementation proposal in the last sections.

## Background and taxonomy

In-context RL (ICRL) means a pretrained agent improves on a new task without
parameter updates by conditioning on its own interaction history. The
[survey](https://arxiv.org/abs/2502.07978) organizes the field by
pretraining signal:

| Pretraining | Idea | Papers here |
| --- | --- | --- |
| Reinforcement pretraining | Outer-loop RL (TRPO, PPO, SAC, off-policy actor-critic) on a sequence-model policy, return summed across all episodes of a trial | RL², PEARL, MELD, TrMRL, AMAGO, ECET |
| Supervised pretraining | Behavior cloning on multi-episode trajectories ordered by improvement (learning histories, noise-annealed demos, curricula) | Algorithm Distillation, Vintix, VLRLA |

Older meta-RL language calls the first family "black-box" or "memory-based"
meta-RL. PEARL and MELD instead infer a task latent explicitly. The common
abstraction is a **trial**: a hidden task is sampled once and the agent plays
K episodes. Memory resets only at the trial boundary, and the objective
or the cloned data rewards improving across episodes.

The rest of this section is a reference for each paper.

### RL² (Duan et al., 2016)

[Paper](https://arxiv.org/abs/1611.02779).

- **ICRL mechanism:** a GRU policy whose hidden state is the learned learning
  algorithm. Input at each step is the observation plus the previous action,
  previous reward and a done flag. The hidden state is **not** reset between
  episodes of a trial, only between trials.
- **RL loop:** sample an MDP, run a trial of n episodes (typically 2), and
  treat the whole trial as one long episode for the outer optimizer, TRPO
  with GAE. The objective is total trial return, so exploration in early
  episodes is rewarded if it pays off later.
- **Rewards:** native task rewards (bandit payouts, MDP rewards, a navigation
  goal reward), fed back into the input.
- **Evaluation:** per-episode return within held-out trials, compared against
  hand-designed algorithms with known guarantees. Bandits were compared
  against Gittins, UCB and Thompson sampling. Tabular MDPs were compared
  against PSRL, BEB and UCRL2.
- **Benchmarks:** multi-armed bandits, random tabular MDPs, visual maze
  navigation in ViZDoom (first episode explores, second exploits).
- **Pros:** the simplest possible formulation. No inner loop or second-order
  gradients. Exploration-exploitation trade-offs are learned end to end.
- **Cons:** on-policy and sample hungry. RNN memory limits long horizons and
  many-episode trials. The outer optimization gets harder as tasks grow. It
  falls short of the best hand-designed algorithms on larger bandit and MDP
  settings. It does not generalize out of distribution.

### Algorithm Distillation (Laskin et al., 2022)

[Paper](https://arxiv.org/abs/2210.14215).

- **ICRL mechanism:** a causal transformer trained to predict actions over
  long *across-episode* subsequences of an RL algorithm's learning history.
  The context must span several episodes so that improvement is
  visible in it. The model then reproduces, and often accelerates, the source
  algorithm's improvement purely in context.
- **RL loop:** two stages. First run a source RL algorithm independently on
  many tasks and save complete learning histories (A3C and DQN-style learners
  in the paper). Then train the transformer with next-action cross-entropy.
  No RL is applied to the transformer itself. At test time it runs online from
  an empty context, and its own transitions fill the context.
- **Rewards:** native environment rewards, which are part of every context
  token.
- **Evaluation:** return versus environment episodes on held-out task
  instances, against the source algorithm, Expert Distillation (cloning
  only expert trajectories, which does not improve in context) and RL².
- **Benchmarks:** Adversarial Bandit, Dark Room, Dark Room (Hard), Dark
  Key-to-Door, DMLab Watermaze (pixels).
- **Pros:** stable supervised training, and it reuses offline data. It showed
  that in-context improvement can be distilled. Its learner is more
  data-efficient than its source algorithm.
- **Cons:** it needs complete learning histories from many single-task runs,
  which is expensive to generate. Learning to improve requires very long
  contexts. Performance is bounded by the improvement present in the data.
  Results are on simple discrete domains, and generalization is limited to the
  task distribution.

### A Survey of In-Context Reinforcement Learning (Moeini et al., 2025)

[Paper](https://arxiv.org/abs/2502.07978).

- **Contribution:** the first dedicated ICRL survey, covering work after AD.
  It defines ICRL as performance improving with context while parameters stay
  fixed ("in-context improvement").
- **Implementation taxonomy:** supervised pretraining (AD-style learning
  histories, curricula, expert prompts, hindsight return-to-go) versus
  reinforcement pretraining (DDPG/PPO/DQN/Muesli variants on sequence models).
  It also covers test-time context selection, theory (behavior imitation of
  source algorithms; transformers implementing TD), and architectures (causal
  transformers dominate; SSMs for cheaper inference; hierarchical designs to
  cut tokens).
- **Benchmarks catalogued:** bandits, Dark Room, XLand 2.0 (XLand-MiniGrid),
  DMLab Watermaze, Procgen, Meta-World ML1/ML45, MuJoCo control.
- **Takeaways:** reinforcement pretraining avoids expert-data dependence and
  appears to generalize better. Open problems are real robotics and sim-to-real,
  multi-agent settings, theory for reinforcement pretraining, and long-context
  cost.
- **Pros and cons as a resource:** the best map of the field and its
  benchmarks. It predates the large robot ICRL work (Vintix's later versions,
  VLRLA) and gives no unified empirical comparison.

### PEARL (Rakelly et al., 2019)

[Paper](https://arxiv.org/abs/1903.08254).

- **ICRL mechanism:** a probabilistic context encoder q(z | c) infers a
  task latent z from a set of transitions (s, a, r, s'). It is
  permutation-invariant, a product of per-transition Gaussian factors.
  The policy and Q-function condition on a sampled z. Adaptation means
  updating the posterior over z from collected context.
- **RL loop:** off-policy SAC over a replay buffer per task. The encoder is
  trained through the critic loss plus a KL information bottleneck to the
  prior. Context batches and RL batches are sampled separately. At test time
  the agent samples z from the prior, acts for an episode, updates the
  posterior, and resamples (posterior sampling, i.e. Thompson-style
  exploration).
- **Rewards:** native dense MuJoCo rewards; also a sparse 2D point-navigation
  variant. Reward is part of every context transition.
- **Evaluation:** test-task return versus meta-training samples, and return
  versus adaptation trajectories.
- **Benchmarks:** MuJoCo Half-Cheetah-Fwd-Back, Half-Cheetah-Vel,
  Ant-Fwd-Back, Ant-Goal-2D, Humanoid-Direc-2D, Walker-2D-Params; sparse
  point robot.
- **Pros:** 20 to 100 times more sample-efficient meta-training than MAML,
  ProMP and RL² in its experiments. Posterior sampling gives principled
  temporally extended exploration, and the latent is interpretable.
- **Cons:** the permutation-invariant encoder ignores order, so it struggles
  with non-Markovian or within-episode-varying tasks. A unimodal Gaussian
  latent fits narrow parametric families. Later results (TrMRL, ECET) show
  it struggles on Meta-World manipulation.

### MELD (Zhao et al., 2020)

[Paper](https://arxiv.org/abs/2010.13957).

- **ICRL mechanism:** unifies task inference with state inference. A
  sequential VAE latent-state model (SLAC-style) is trained on images *and
  rewards*. Its posterior belief over the latent state therefore also encodes
  the task, so meta-RL reduces to POMDP RL in the latent space.
- **RL loop:** alternate model updates (ELBO over observations and rewards)
  with SAC actor-critic updates on the latent belief. There is one replay
  buffer per training task. At test time the belief updates online from a new
  task's images and rewards, with no gradient steps.
- **Rewards:** dense simulated rewards for the sim tasks. On the real robot,
  a sparse completion signal for correct cable insertion.
- **Evaluation:** success and return on new task variations; the real robot
  must insert into a new location and orientation within two episodes.
- **Benchmarks:** image-based simulated tasks (cheetah at varying velocities,
  peg insertion at varying targets, mug placement with unknown weight); real
  5-DoF WidowX Ethernet-cable insertion after about 8 hours of real-world
  meta-training. The authors call this the first image-based meta-RL on a
  real robot.
- **Pros:** works from pixels, uses off-policy data efficiently, and shows
  real-robot feasibility. The world-model latent shares structure between
  state and task.
- **Cons:** it needs a reward-predictive generative image model, which
  carries reconstruction cost and capacity limits. It handles narrow
  parametric task families, and real-world meta-training still needs
  engineered task resets.

### AMAGO (Grigsby, Fan, Zhu, ICLR 2024)

[Paper](https://arxiv.org/abs/2310.09971).

- **ICRL mechanism:** a long-context causal Transformer over entire
  multi-episode rollouts (context length defaults to the full horizon). Each
  timestep token embeds the observation, previous action, reward and time
  information, plus an optional instruction.
- **RL loop:** **off-policy** with parallel actors. One shared sequence model
  sits under actor and critic heads, trained by one optimizer. The loss
  combines a TD critic term, a policy-gradient actor term and a filtered-BC
  term, kept on scale by PopArt. It uses REDQ-style critic ensembles and
  *multi-gamma* (losses for many discounts in parallel). Stability comes from
  extra LayerNorms (NormFormer), σReparam and leaky activations.
- **Rewards:** native rewards, focused on **sparse** goal-reaching. Hindsight
  instruction relabeling rewrites multi-step instructions to subgoals actually
  achieved and recomputes rewards, which is what makes sparse exploration
  tractable.
- **Evaluation:** POPGym normalized score, meta-test success across
  episodes, and success on multi-step instructions.
- **Benchmarks:** POPGym (39 envs, average normalized 0.95), Passive and
  Active T-Maze (memory up to 10k steps), Half-Cheetah-Vel, Dark Key-to-Door
  (adapts faster than AD), Wind, Meta-World ML1, Package Delivery, MazeRunner,
  instruction-conditioned Crafter.
- **Pros:** scalable, stable off-policy training of Transformer memory. It
  solves very long memory tasks, and hindsight relabeling turns sparse reward
  into a learnable signal. The code is public and often used as a baseline.
- **Cons:** many interacting components (multi-gamma, PopArt, filtered BC,
  ensembles). ML10/ML45 were left for future work because of unknown task
  identity and reward-scale differences. Long contexts can overfit small task
  distributions, and full-rollout attention is costly.

### TrMRL (Melo, ICML 2022)

[Paper](https://arxiv.org/abs/2206.06614).

- **ICRL mechanism:** each transition (state, action, reward, done) becomes a
  "working memory". A transformer encoder over the N most recent transitions
  refines them, layer by layer, into an "episodic memory". The paper argues each
  layer forms a consensus representation that lowers Bayes risk. The
  policy reads the current timestep's output.
- **RL loop:** on-policy PPO. Each task's E = 2 episodes are concatenated into
  one trajectory, and batches mix tasks. T-Fixup initialization is required
  for stable transformer RL. At test time parameters are frozen.
- **Rewards:** native MuJoCo and Meta-World shaped rewards in the transition
  tokens.
- **Evaluation:** meta-training curves, test return or success, and
  out-of-distribution parameters (velocities 3.0 to 4.0 after training on
  0.0 to 3.0).
- **Benchmarks:** MuJoCo AntDir and HalfCheetahVel; Meta-World ML1 (Reach,
  Push) and ML45 on its training tasks.
- **Pros:** simple, adapts within the first episode (about 20 steps on
  HalfCheetahVel), beats RL², PEARL, MAML and VariBAD on several tasks, and
  is better out of distribution.
- **Cons:** the short sliding window gives limited cross-episode memory.
  Training is sensitive (T-Fixup needed; deeper or longer models hurt).
  It is on-policy only, and results use three seeds.

### Vintix (Polubarov et al., 2025)

[Paper](https://arxiv.org/abs/2501.19400).

- **ICRL mechanism:** an AD-style cross-domain "action model" of about 300M
  parameters: a TinyLlama-style decoder, 24 layers, 8192-transition context,
  ALiBi so sliding-window KV caching has no positional drift. Each token
  stacks the previous action, previous reward and current observation.
  Per-dimensionality-group MLP encoders and decoders share one backbone. The
  model sees no task ID.
- **RL loop (data):** **Continuous Noise Distillation.** Instead of running
  RL per task, take a demonstrator policy and generate synthetic learning
  histories by mixing its action with uniform noise, annealing the mix weight
  ε from 1 (random) to 0 (expert) over the trajectory. The noise schedule was
  tuned per task. The data has about 1.6M episodes and 222.7M timesteps.
- **RL loop (training and inference):** MSE next-action prediction over
  multi-episode subsequences, with no RL on the model. Inference is a cold
  start from an empty context with sliding-window eviction.
- **Rewards:** native rewards, scaled per task, with normalized observations
  so the task cannot be read from raw scales and must be inferred from
  context.
- **Evaluation:** cold-start many-shot inference, with demonstrator-normalized
  return after convergence (average over 100 episodes). Generalization was
  tested on parametric variations (MuJoCo viscosity and gravity,
  Industrial-Benchmark setpoints) and held-out tasks. Baselines were JAT and
  REGENT.
- **Benchmarks:** 87 tasks across MuJoCo (11), Meta-World (45), Bi-DexHands
  (15) and Industrial-Benchmark (16).
- **Pros:** cheap improvement data from a single expert per task, scale across
  domains, observable self-correction, and a released dataset and tools.
- **Cons:** it does not exceed the demonstrator. Held-out tasks give mixed
  results (Door-Unlock about 47%, Door-Open-Inward about 31%, Bin-Picking
  random, Hand-Kettle below random). It uses vector observations only, and
  the noise schedules need tuning.

### ECET (Shala et al., ICLR 2025)

[Paper](https://www.iclr.cc/virtual/2025/poster/29485) · [proceedings PDF](https://proceedings.iclr.cc/paper_files/paper/2025/file/bbc0df00853596fcf4bbcbef853a880a-Paper-Conference.pdf).

- **ICRL mechanism:** hierarchical memory. An intra-episodic transformer
  compresses T transitions (s, a, r, done) of each past episode into one
  episode embedding. A cross-episodic transformer *without positional
  encoding* treats a FIFO set of E episode embeddings as a set and outputs a
  task embedding. The Gaussian policy reads that embedding and the current
  state. Attention cost is O(E² + T²) instead of O((E·T)²).
- **RL loop:** the RL² framework with PPO as the outer loop (garage
  implementations) and the Gaussian NLL critic. A FIFO of E = 25 past
  episodes, T = 5 transitions sampled per episode. Budgets were 10⁷ (MuJoCo),
  5×10⁷ (Meta-World) and 2.5×10⁷ (ManiSkill) steps, with five seeds.
- **Rewards:** native shaped rewards. Success is the metric on manipulation.
- **Evaluation:** few-shot adaptation on unseen parametric variations and
  unseen tasks; average rank across tasks; 50-episode rollouts to see
  behavior across episodes; anytime (wall-clock) performance.
- **Benchmarks:** MuJoCo AntDir, HalfCheetahDir, HalfCheetahVel; Meta-World
  ML1 (Push, Reach), ML10, ML45; ManiSkill StackCube and PickSingleYCB from
  RGB. Baselines: MAML, RL², PEARL, VariBAD, TrMRL, AMAGO (ML10/ML45).
- **Pros:** efficient long cross-episode memory and the best average rank.
  ECET is the only method above 0.8 training success on ML10 and above 0.6
  on ML45. Its ablations are informative (order-free episode sets help;
  flat transformers do worst).
- **Cons:** held-out test success is still about 0.35 (ML10) and 0.4 (ML45).
  It exploits task similarity rather than broad generalization. Sampling only
  T transitions per episode discards detail.

### VLRLA (Shi et al., October 2026)

[Paper](https://arxiv.org/abs/2610.19517).

- **ICRL mechanism:** deployment-time adaptation of a pretrained VLA (π0.5;
  also LingBot-VLA and FastWAM) through a recurrent memory over
  C_t = {(o_i, a_{i:i+h}, r_i, d_i)}. The memory holds observations, action
  chunks, rewards and done flags across multiple episodes of one task.
  Transformer-XL-style segment memory handles long trials.
  - *VLRLA-simp:* a frozen VLM prefix and a trainable recurrent transformer
    with an MLP action-chunk head.
  - *VLRLA-bridge:* the VLM and π0.5 action expert stay frozen. A 6-layer,
    width-512 bridge reads the VLM K/V cache and history, then writes a rank-64,
    zero-initialized residual into that cache. Initial behavior equals the base
    policy.
- **RL loop:** AD-style. Learning histories come from (1) PPO in RoboTwin with
  domain randomization (25 iterations, 256 envs, failures kept), (2) a
  human-in-the-loop curriculum on a real robot (unassisted rollouts, then
  partial corrections, then demos; 35% to 93% success), or (3) hindsight
  relabeling of demos under an underspecified instruction. The loss is MSE
  (simp) or flow-matching through the frozen expert (bridge). At deployment
  weights are fixed and memory accumulates across episodes.
- **Rewards:** native sparse success in simulation; binary relabeled
  match/mismatch for the cross-episode task. No learned reward model.
- **Evaluation:** success versus episode index; 128 randomized instances and
  five seeds in simulation; small real-world cohorts (45 seen, 25 unseen,
  44 cross-episode runs). Baselines were π0.5, GRPO (parameter updates) and
  RoboTTT.
- **Benchmarks:** RoboTwin 2.0 (12 tasks), a real arm for fruit placement,
  and a Franka for cross-episode placement. Average success was 63.4% versus
  50.9% for π0.5 and 60.0% for GRPO. Unseen tasks gained less (60.6% versus
  60.8% for GRPO).
- **Pros:** the closest analogue to this repository. It uses a frozen VLA,
  a trainable memory reading native K/V, and a zero-initialized residual that
  keeps the base policy intact. It requires no test-time gradients, and its
  history-generation recipes are reusable.
- **Cons:** small real-world samples without statistical tests. The only
  simulation benchmark is RoboTwin, and RoboTTT was reimplemented. Gains on
  unseen tasks are modest. It depends on backbone representation quality.
  RL-generated histories are compute-heavy.

## Comparison across papers

| Method | Training signal | Memory | Reward source | Main benchmarks | Weights at test |
| --- | --- | --- | --- | --- | --- |
| RL² | TRPO over whole trials | GRU across episodes | Native | Bandits, tabular MDPs, ViZDoom | Frozen |
| AD | Next-action BC on learning histories | Causal transformer, multi-episode | Native | Bandit, Dark Room, Key-to-Door, Watermaze | Frozen |
| PEARL | SAC with a KL bottleneck | Order-free Gaussian latent | Native dense | MuJoCo locomotion, sparse point | Frozen |
| MELD | SAC on a reward-predictive latent model | Sequential VAE belief | Dense sim; sparse real | Image MuJoCo, real WidowX | Frozen |
| TrMRL | PPO | Transformer over N recent transitions | Native shaped | MuJoCo, Meta-World ML1/ML45 | Frozen |
| AMAGO | Off-policy actor-critic, multi-gamma | Full-rollout transformer | Native sparse + hindsight relabels | POPGym, T-Maze, Meta-World ML1, Crafter | Frozen |
| ECET | PPO (RL² framework) | Intra- and cross-episode hierarchy | Native shaped | MuJoCo, Meta-World ML1/10/45, ManiSkill | Frozen |
| Vintix | MSE BC on noise-distilled histories | 8192-step decoder, ALiBi | Native, rescaled | 87 tasks across MuJoCo, Meta-World, Bi-DexHands, IB | Frozen |
| VLRLA | AD-style MSE or flow matching | Transformer-XL bridge on frozen VLA K/V | Sparse success, relabeled binary | RoboTwin 2.0, real arms | Frozen |

Cross-cutting lessons for the design below:

1. **Feedback channels.** Every method feeds back (previous action, reward,
   done). Without a reward channel a learner can identify dynamics but cannot
   learn reward-dependent behavior.
2. **Trial objective.** RL learners optimize summed return over K episodes
   with memory carried across boundaries. AD-style learners use improving
   histories. DPT-style learners instead need task-specific expert targets
   for query observations and informative interaction contexts; monotonic
   improvement in the context is not a requirement.
3. **Sparse reward needs help.** AMAGO uses relabeling, VLRLA uses relabels
   and curricula, and Vintix and AD use dense improvement data.
4. **Controls.** A no-memory control, a reset-between-episodes control and a
   source-algorithm or oracle reference separate ICRL from plain
   generalization.
5. **Stability.** TrMRL needed T-Fixup, AMAGO needed several stabilizers, and
   ECET kept memory small.

## Warm-starting a fresh recurrent adapter

There is no universal prerequisite to train an ICRL teacher first. Distinguish
initial behavior, supervised adaptation pretraining, and reinforcement
pretraining:

| Route | What supplies the signal | Requires a pretrained recurrent ICRL policy? |
| --- | --- | --- |
| RL² / reinforcement pretraining | Returns from the learner's own multi-episode task trials | No |
| Algorithm Distillation | Histories of an ordinary source RL algorithm learning each training task | No |
| DPT / Vintix II | Task-specific expert action labels; context may come from random or suboptimal policies | No |
| VLRLA | RL improvement histories, staged human corrections, or hindsight-assembled demonstrations | No |
| Distill an existing recurrent agent | A trained recurrent teacher's action distribution | Yes; an optional later reuse strategy |

[DPT, Algorithm 1 and Section 3](https://arxiv.org/html/2306.14892)
separates the interaction dataset from the target action at a query state.
Training contexts can be random, expert-generated or algorithm-generated.
The task-specific optimal policy supplies labels; Section 5.3 also evaluates
labels supplied by RL-trained policies. An analytical oracle can supply labels
on tractable benchmarks. The student must not receive the oracle's private task
information in its inputs.

[Vintix II, Sections 3.1–3.3](https://arxiv.org/html/2604.05112v1)
collects diverse, noisy interactions and labels query actions with a
demonstrator. Context retains the actions actually applied and their resulting
rewards. It uses flow matching to represent multimodal continuous action
distributions. This supports a DPT-inspired CTM experiment, not a claim that
the paper validates CTM or our native pi0.5 interface. Its shuffled,
query-conditioned contexts also differ from a chronological recurrent stream.

[VLRLA, Sections 4.1–4.2 and Appendix A.1–A.2](https://arxiv.org/html/2610.19517v1)
zero-initializes its KV-residual output to preserve the base motor behavior,
then trains its bridge with flow matching on action targets. Simulation source
histories come from ordinary PPO fine-tuning of the base VLA, not a previously
trained recurrent ICRL agent. Its frozen action expert is a component of the
student and is distinct from the data-generation process. Our current native
bridge modifies flow velocity rather than KV, so the architecture is not an
exact VLRLA implementation.

For a fresh CTM, preserving a competent frozen motor and initializing its
residual to zero is an initial-behavior guarantee. It does not train the CTM
to use rewards. Cloning an unchanged, history-independent motor can be solved
while ignoring history, and all-zero residual targets provide no reason to
learn adaptive memory. A supervised warm start therefore needs either genuine
improvement histories or task-dependent action labels paired with informative
contexts. If those are unavailable, full-trial reinforcement pretraining is
the direct supported alternative.

For our controlled hidden-rotation task, an inverse-rotation transformation of
a competent motor's actions is a possible **training-only label generator**.
That is our proposed engineering extension, not a demonstrated result from
these papers. It requires decoder checks, an empirical competence gate, and
strict exclusion of the hidden angle from student inputs. A hand-coded
feedback-driven teacher is another possible source algorithm, not a
literature-mandated bootstrap.

Save initialization weights per benchmark family, observation/action interface,
architecture and training-data version. Train on the declared training-task
split, evaluate adaptation with weights frozen on held-out tasks, and reset
transient recurrent state at each new trial. Keep direct reinforcement
pretraining as a comparison to any supervised warm start; include all teacher
and data-generation costs.

## Methods beyond AD and DPT for a PPO history dataset

Snapshot: 2 November 2026. The question: once Flora-reward PPO histories
exist (one graded terminal score per episode, a suboptimal final policy), which
supervised ICRL methods besides AD, DPT and CND are worth running? RL² is set
aside as hard to tune. Candidates must keep the plain causal decoder and the
bounded action residual ([PAPER.md](../PAPER.md)). Results below are from
abstracts and summaries unless noted. The DIT and S-ICQL method sections were
checked against the frozen-steering collector on 3 November 2026; see the
[collection audit](../../outputs/robocasa-rollout-capacity-3248-20261103-r1/META-LEARNING-COLLECTION-AUDIT.md).

### Recommended

1. **DIT** ([Dong et al., ICML 2025](https://arxiv.org/abs/2601.20116)).
   Uses the dataset's actual behavior actions with an advantage-weighted loss.
   Its separate in-context Q/V estimators learn from trajectory returns with
   Bellman regularization; their difference weights action imitation by
   exp(A/η). Final-PPO teacher relabels belong to DPT and are not the original
   DIT targets. This permits suboptimal source policies but still requires
   implementing and qualifying the value estimators and weighted objective
   ([method §4.2](https://arxiv.org/html/2601.20116v1#S4.SS2)).
2. **Value-based offline ICRL on an AD backbone**
   ([Tarasov et al.](https://arxiv.org/abs/2502.17666), RLC 2026;
   [SICQL](https://arxiv.org/abs/2506.01299), ICLR 2026). AD's causal model
   plus expectile value fitting and advantage-weighted policy extraction.
   Tarasov et al. report about 30% over AD across more than 150 GridWorld and
   MuJoCo datasets and about 2× on XLand-MiniGrid; conservatism helped almost
   everywhere. The four intended methods are AD, DPT, DIT and value-based
   offline ICRL. They share one teacher corpus (PAPER.md, 2026-11-03 source-campaign
   decision), while using
   different labels and value objectives; this is not a literal 2×2 of AD/DPT
   labels and weighting. S-ICQL also learns a world-model prompt, so an IQL
   objective on the existing decoder should be identified as an adaptation
   rather than a complete S-ICQL reproduction
   ([method §3](https://arxiv.org/html/2506.01299v3#S3)).
3. **Return-sorted curriculum**
   ([CEC, Shi et al., NeurIPS 2023](https://arxiv.org/abs/2310.08549)).
   Reorder episodes into chains of rising return and clone them; CEC's
   continuous-control results are on RoboMimic mixed-quality demonstrations.
   Nearly free, and it tests whether AD needs real learning dynamics or only
   rising order. Sorting by Flora score bakes reward-model errors into the
   curriculum, so add a simulator-success-sorted variant for diagnosis only.
4. **ICEE** ([Dai et al., ICLR 2024](https://arxiv.org/abs/2403.06826)),
   if time allows. Decision-Transformer-style conditioning on a cross-episode
   return-to-go ("beat earlier episodes"), removing the need for ordered
   histories. Reported to learn in tens rather than hundreds of episodes on
   grid worlds only; the test-time target for a graded terminal reward is an
   extra design choice.

### Deprioritized

- **DICP** ([Son et al., ICLR 2025](https://arxiv.org/abs/2502.19009)):
  in-context dynamics prediction plus planning. Strong on Meta-World, but
  predicting dynamics in VLA feature space over H400 episodes is impractical.
- **RA-DT** ([Schmied et al.](https://arxiv.org/abs/2410.07071)): retrieves
  relevant sub-trajectories instead of holding whole episodes in context. A
  fallback if multi-episode context length binds, not a method arm.
- **Task-encoder offline meta-RL** (FOCAL, CORRO, UNICORN): does not fit the
  plain-decoder constraint.
- **Frozen-VLA memory without RL training** (Zeva
  [2608.30880](https://huggingface.co/papers/2608.30880), SOMA
  [2603.24060](https://arxiv.org/abs/2603.24060), WeaveLA
  [2606.17463](https://arxiv.org/abs/2606.17463)): related work, not
  baselines; only abstracts were seen.

### Implications for PPO collection

- Needed: the policy version for each episode (AD ordering, DPT/DIT
  relabels), the residual Gaussian's mean, std and log-probability per
  decision (importance weights, AWR), and the raw Flora score with the
  simulator-success sidecar.
- The RoboCasa residual PPO driver
  (`scripts/diagnostics/robocasa_residual_ppo.py`, checked 2 November 2026)
  already records all of this. `pending-NNN.pt` holds every per-chunk record
  (features, noise seed, base and executed chunks, u, log-probability, value)
  together with the behavior policy's weights before the update, so its mean
  and std are recomputable exactly. `boundary-NNN.pt` follows each update,
  `labels-NNN/` holds the Flora request and outputs, and the monitoring JSON
  holds simulator success per episode in both arms. `history.npz` carries only
  the decoder's AD fields and is written at the end of the run.
- The retention rule allows pruning uncited checkpoint payloads. For any run
  whose histories feed a meta-learner, keep every `pending-NNN.pt`,
  `boundary-NNN.pt`, `labels-NNN/` and monitoring record: they are the only
  copy of the behavior-policy statistics and raw scores. `residual_ppo.history_sidecar` exports these; the
  [residual PPO plan](../../outputs/robocasa-residual-ppo-20261101-r1/PLAN.md)
  requires them and per-update checkpoints.
- Value-weighted methods optimize toward Flora's score and can exploit its
  errors more than AD. Report true simulator success beside Flora score for
  every arm, with the same rising-score, flat-success check as the PPO pilot.

## Language steering of pi0.5

Snapshot: 29 October 2026. This bears on any hidden-target task that changes
the instruction (Option B, VLRLA's underspecified-instruction relabels). The
evidence is consistent: pi0.5 encodes the instruction but rarely lets it pick
the target when the scene implies another one.

- **Target swap, fixed scene.** [Encoded but Not in Control](https://arxiv.org/html/2610.06235v1)
  changes only the target noun among visible LIBERO-Object objects. pi0.5
  approaches the instructed target in 13.0% of episodes (11.5% success) and the
  original target in 86.5% (69.5% success); on a real arm, 10.8% versus 80.8%.
  Linear probes recover the instructed target near ceiling, so the failure is
  control, not encoding. Instruction tokens carry about 26–28% of
  attention-based action contribution on LIBERO and about 1.7% on RoboTwin.
  No fix is tested.
- **Same finding elsewhere.** [BAS-VLA](https://arxiv.org/html/2609.23650)
  reports OpenPI pi0.5 on LIBERO-Object at 98.5% clean and 34.0% under target
  swap, with new-target success near 0% on several swaps.
  [LIBERO-PRO](https://arxiv.org/abs/2510.03827) reports nearly unchanged
  trajectories under corrupted or nonsense instructions, and
  [LIBERO-Plus](https://openaccess.thecvf.com/content/CVPR2026/html/Fei_LIBERO-Plus_A_Progressive_Robustness_Benchmark_for_Visual-Language-Action_Models_CVPR_2026_paper.html)
  that models tend to ignore language; neither abstract isolates pi0.5's
  language result.
- **Residual on a frozen pi0.5.** BAS-VLA trains a small residual on matched
  clean, control and semantic-breaking instruction triplets. New-target success
  on four easy swaps rises from 2.3% to 68.5%; a norm-matched random residual
  gives 1.5%. This is the closest analogue to a bridge residual steering a
  frozen motor.
- **Inference-time contrast.** [CAG](https://arxiv.org/abs/2602.17659)
  contrasts the VLA with a language-unconditioned vision-action branch. With
  pi0.5 on LIBERO-CF it adds 9.7 points of language following training-free,
  or 15.5 with a trained vision-action module (abstract figures).
- **Activation injection.** [Not All Features Are Created Equal](https://arxiv.org/abs/2603.19233)
  injects task A's action-expert activations while pi0.5 views task B's scene;
  pi0.5 executes task A in 99.6% of episodes. On a real arm the injected program
  grasps at recorded coordinates even after the object moves. Action-expert
  steering is strong but scene-blind. [Häon et al.](https://proceedings.mlr.press/v305/haon25a.html)
  steer pi0 and OpenVLA through sparse feed-forward directions.
- **Training-side fixes.** Counterfactual instruction labels or negatives
  ([CAST](https://arxiv.org/abs/2508.13446),
  [CIG](https://github.com/SeeYooLeo/CIG-RoboCasa-Kitchen),
  [FineVLA](https://arxiv.org/abs/2605.27284)) improve fine-grained following.
  CIG self-reports pi0.5 on RoboCasa at 65.8% to 71.3%; CAST and FineVLA
  abstracts do not name pi0.5.

Implications here: changing the prompt will not by itself move the frozen
RLinf pi0.5 motor to a new target, so a language hidden-variable task needs the
learner to steer through a residual (KV or action expert) and a target-swap
check of the base motor first. When the scene alone identifies the goal, vision
dominates, which supports keeping the PoC's hidden variable in the action
rotation. The pi0.5 paper ([arXiv 2504.16054](https://arxiv.org/abs/2504.16054))
reports better language following than pi0; its numbers were not checked here.
