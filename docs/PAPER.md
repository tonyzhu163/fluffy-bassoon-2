# Few-shot decision learning for frozen robot policies

Can a robot use one attempt to make a better decision on the next, on a manipulation task held out from meta-training? We propose training a Decision-Pretrained Transformer (DPT) to read past interactions and choose an action the frozen motor can execute. A trial holds a task and an environment condition fixed across fresh resets. The controller learns offline across many such trials. At deployment its only update is to its memory.

## The learning problem

Consider a robot asked to put a bowl on a stove. A previous reach shows the wrist arriving several commands late. On a fresh pose the robot still has to find the bowl and plan a reach. What it can reuse is the relationship between the commands it sent and the motion it observed. Whether slowing the approach helps under delay, and whether it costs success at normal timing, can be measured on the same benchmark task.

Build each training example from an earlier **support** history, a current **query** observation, and a decision target at that exact observation.

1. Sample a training task and a condition. Run the base policy or a mixture of feasible strategies on one or more resets. Save public observations, issued actions, observed motion, native feedback and episode boundaries, including failed attempts. Keep the physical execution record for alignment. Give the learner only signals available to the deployed robot.
2. Reset to a fresh pose with the same task and condition. At a query decision, label feasible continuations using a competent condition-aware teacher queried there, or fork the saved state, execute alternatives and measure native outcomes. Repeat stochastic continuations when ranking them. Retain ties and uncertainty. Keep teacher inputs, branch outcomes, hidden settings and future frames out of the query input.
3. Train a causal history encoder and action head to predict the labeled decision from support, instruction and current-episode observations. Train on empty support as well as short prefixes, and on matched queries where different support calls for different actions. If the same memoryless teacher always gives the same label at those queries, its actions supply no training signal for that distinction. More PPO iterations alone do not construct these examples.

For a discrete set of continuations, fit the distribution of supported teacher choices by cross-entropy. A practical first controller selects among frozen-policy proposals or simple executable variants, including the native proposal. If two strategies still fit the evidence, retain probability on both and execute one coherent strategy through its decision horizon. Averaging incompatible reaches can produce a command that misses both targets. Measure the best fixed choice and how much a condition-aware chooser can gain using that very same menu. A reader that infers the condition perfectly can still fail if every available action misses the grasp. This is a DPT-style approximation with measured or teacher labels. The original DPT predicts an optimal query action from an interaction dataset. [Original DPT](https://arxiv.org/abs/2306.14892)

## First model

Use the qualified LIBERO π0.5 checkpoint as the frozen motor. Keep its camera preprocessing, checkpoint quantile transforms and action decoding. Put a small causal Transformer beside it. The first model scores a fixed set of executable choices at a declared decision point, initially the reset before attempt two. π0.5 still sees the current cameras, robot state and instruction and generates the action chunks throughout that attempt. [OpenPI motor](https://www.pi.website/blog/pi05) · [Runtime qualification](METHODS.md#libero-evaluation)

| Component | Proposed first implementation |
| --- | --- |
| Support tokens | Within each episode, pack five physical controls per token in control order. Preserve each issued command and the following public end-effector displacement, gripper state and reward. Keep within-token timing and validity, including commanded waits. Mark resets with an episode-boundary feature and use the decoder's relative position bias. |
| Query token | Project the current public robot state and pooled frozen image/instruction features. For the prefix comparison, also supply the query's own completed control tokens up to the decision. |
| Reader | Start with the repository's causal decoder at two layers, width 128 and four attention heads. The query attends to valid preceding support and current-episode tokens. Weights stay frozen during retries. Clear state between trials and mask previous-episode tokens for the cleared arm. |
| Decision head | A categorical head scores the declared execution modes. An initial mode can govern a whole retry. Include the native five-control replanning mode as an available action. Keep the same choice set and validity masks in the history and current-only arms. |
| Training | Use cross-entropy on a soft target over the best measured or teacher-labeled choices at the query. Split mass across measured ties and leave unresolved rankings unlabeled. Failed supports stay in context. All-failed queries remain in the physical evaluation and supply no successful categorical target. Train on a mixture of retained and empty prior context. |

Normalize public inputs on fitting data. Do not expose timing IDs, the hidden goal in feedback pilots, simulator queues, branch outcomes or future observations. Hold the motor backend fixed between label collection and evaluation, or verify replay and native success for the migrated backend. The existing noise-policy and KV-adapter code provide building blocks. The categorical retry selector and its benchmark fit remain proposed. [Causal decoder](../src/fluffy_bassoon/meta_rl/causal_decoder.py) · [Implemented interfaces](METHODS.md)

For continuous control, make the same reader output a context vector for a small KV adapter in the frozen π0.5 action expert. Train with a masked flow-matching loss against a competent teacher's action chunk at the exact query observation. First give the adapter the true condition on development tasks and test native execution. This checks whether the adapter can realize the correction before its success depends on reading history. [VLRLA](https://arxiv.org/abs/2610.19517) · [Flow matching for DPT](https://arxiv.org/abs/2604.05112)

For a frozen world-action model (WAM), keep the history reader and give the scoring head a candidate token for each proposed action chunk and its predicted visual future. The past tape can include discrepancies between predictions made at the time and motion already observed. Train on native outcomes from executing the corresponding chunks. Evaluate on the same actions with and without their predicted futures, charging the proposal budget in both arms. [DreamZero's joint video/action model](https://arxiv.org/abs/2602.15922)

A demonstration can supply the goal or a successful strategy. An attempt supplies evidence about what happened when this robot tried an action. For a demonstration-conditioned experiment, give both arms the same demonstration and vary access to the robot's subsequent attempt. That contrast measures the additional value of trying. [In-Context Robot Transformer](https://arxiv.org/abs/2408.15980) · [Watch, Try, Learn](https://arxiv.org/abs/1906.03352)

### A matched two-attempt trial

1. Assign a task, a persistent condition, two different valid reset states, and independent policy and environment randomness. Hold the condition across both attempts. Run one common support policy from the first reset, recording the issued commands, observed motion and native reward. Keep the support even if it succeeded.
2. At the second reset, create paired retained and cleared query branches from the same state and randomness. Run the same frozen selector and motor in each arm for the same physical budget. Use the actual continuation selected by each arm. In a diagnostic for online timing recognition, execute the same short opening in both arms and charge it to the attempt. At the decision point, give both arms the resulting current-episode prefix and give the retained arm the previous attempt as well.
3. Score unconditional attempt-two native success and the paired gains and losses for each task and condition. Use a separate development sweep of the full action menu to quantify the outcome ceiling and decide which labels to collect. Evaluate the official held-out panel after freezing the recipe, case catalogue and sample size. Across eight tasks and two timing conditions, each additional pose pair per task and condition costs 16 shared support episodes and 32 physical queries per fit for the two primary arms. Donor, fixed and current-only controls add their own query costs.

Use a common support attempt first to isolate the effect of reading it. Then let the frozen learner generate its own experience over three attempts and compare with cleared retries at equal physical-control budgets. Keep the observed history of the current episode available to both. Count support and inference costs, publish success at each attempt and show cumulative success separately. Freeze task coverage, conditions, fit selection and episode counts using development data. Include every valid test case, even when the first attempt succeeded. A result on timing alone supports a claim about timing. Extend to another mechanism for broader transfer.

## When to scale

**Scale the action coverage first.** On the eight-task development panel, the motion rule scored 20/32, the strongest fixed mode scored 18/32 and the union of the two measured modes was 21/32. Both modes failed in 11 of the 16 delayed queries. Retain default and fixed paced execution as controls. Qualify additional continuations on fitting and development tasks, such as a delay-aware replan schedule or a short grasp-recovery routine. Measure how often a changed execution choice turns failure into success, where those changes occur across tasks and independent starts, and how many positive labels remain after pairing. Compare a competent condition-aware selector with the best fixed strategy and with selectors given public prior or current motion. An outcome oracle that sees every branch is an upper bound on this menu. It can choose using outcome information a real policy lacks.

**Scale the training data after the small reader uses history on fresh development tasks.** The existing fitting examples can exercise training and inference on the small model now. Once the fitting menu supplies successful alternatives, use the registered eight-task fitting subset and hold model size fixed. Look for a repeatable paired advantage from relevant support over cleared or mismatched support and the equally trained current-only controller. Inspect the per-task effects and failure cases, especially whether the gains come from one task or merely from reconstructing the binary timing label. If fixed pacing or a short current prefix accounts for the result, redesign the intervention to test persistent information the current prefix cannot already reveal. Decide what gain justifies support collection and latency from the measured cost before setting the confirmatory sample size.

**Distinguish training breadth, depth and model capacity.** Expand the registered fitting subsets from eight to sixteen to twenty-four tasks at matched total training trials and optimizer updates to measure the value of task variety. Separately add independent trials and conditions per task at fixed breadth. Keep the same development panel and show variation over independent fits. Increase decoder size only if the action menu has measured headroom and the small reader still leaves a reproducible gap to an informed selector after accounting for data coverage and information available at test time. Open the eight official test tasks once the model, baselines and protocol are frozen. Run a second persistent mechanism before claiming transfer beyond timing. ## What the existing experiments establish

The corrected multi-task RoboCasa comparison found no reliable held-out history advantage. Its training histories traversed different scene seeds while its evaluation retried the same scene. The controlled OpenDrawer reader subsequently scored **95.83% with support versus 50% cleared** on measured three-choice branches with a persistent signed offset. On a separate small development panel the full adapter with privileged condition and timing succeeded **3/8**, the base motor **2/8**, and the teacher **8/8**. These measurements explain why the benchmark experiment tests both the information in history and the motor's ability to act on it. [Corrected comparison](../outputs/robocasa-six-task-scale-20261113-r1/RESULT.md) · [Reader experiment](../outputs/robocasa-feedback-advantage-20261117-r1/RESULT.md) · [Motor experiment](../outputs/robocasa-full-history-adapter-20261117-r1/EXECUTION.md)

A failed placement illustrates why actions and motion belong beside rewards in the support. If the bowl reached the plate and received zero reward, trying the other destination may help. If the gripper dropped the bowl before reaching either destination, the same zero says little about the goal. Compare the learner with both a simple repeat-on-success/switch-on-failure rule and a rule that checks whether the placement finished. In the two-destination fitting pilot, paced execution placed the bowl on 8/8 delayed queries where default execution scored 0/8. On the same starts under normal timing, pacing scored 6/8 and default execution 7/8. Always pacing is the fixed comparator for testing whether carrying the first attempt improves the next decision. [Failure-interpretation experiment](../outputs/paper-design-audit-20261118-r1/ICML.md) · [Native bowl outcomes](../outputs/libero-bowl-decisions-20261118-r1/RESULT.md#pacing-under-delay)

Across all eight LIBERO-Pro2.0 development tasks, a demonstration-calibrated motion rule chose default or paced execution on 32 paired retries. It identified timing on every support and succeeded on 20/32 queries. The stronger fixed strategy succeeded on 18/32. Even with access to both measured outcomes, only 5/16 delayed queries had a successful continuation. This bounds what a decision learner could gain from choosing between these two strategies on this panel. [Paired development retries](../outputs/libero-retry-headroom-20261119-r1/RESULT.md)

Timing can be inferred from motion alone. To establish reward-dependent adaptation, hold the support actions and observed motion fixed and vary valid feedback, for example by scoring a completed placement against either of two possible goals. Measure whether the resulting decision improves native success on a fresh reset. To establish learned exploration, compare learner-chosen probes to a fixed probe under the same total interaction budget. These are mechanism tests. The benchmark comparison supplies the evidence for transfer. [Verified findings](FINDINGS.md)
