# Frozen motor and Gate 1 audit

November 19, 2026. The original checker could pass on the 40 shifted trials while failing the registered 48-trial gain. It also changed the seed by embodiment, compared resets only within an arm pair, and could substitute a cached prompt for the instruction returned at reset. The repaired entry points address all three issues. This was a Mac source audit using 0 GPU-hours. Gate 1 success and rendering drift on this panel remain unmeasured. ## Gate decision and rendering drift

The development decision requires all 48 paired trials, at least **36 oracle successes**, at least **24 more successes than nominal** across those same trials, and an oracle success count at least as high as nominal on the eight `fam_nom` pairs. This preserves the scaffold's aggregate interpretation of BASE non-regression. Every individual BASE outcome is recorded. For example, 30 oracle versus 10 nominal successes on the shifted trials plus 8 versus 8 on BASE would have passed the old checker. The registered gain is only 20/48, so the repaired checker fails it. Smoke emits a null gate decision. [Plan](PLAN.md) · [Checker](gate1_check.py)

An earlier independent LIBERO experiment observed four motor-facing channel values differ by one intensity unit at control 110 despite identical reset fields and matching action prefixes. That was a different task condition. Here, the two independently executed `fam_nom` arms record per-query view, state and proposed command-prefix digests. `base_drift` identifies the common query controls that differ in each field, the two query counts, and any endpoint disagreement. Post-reset pixel differences alone do not classify their cause or change the registered success thresholds. [Earlier execution evidence](../libero-command-grasp-20261119-r1/EXECUTION.md)
