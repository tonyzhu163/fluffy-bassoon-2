# Can an expert finish the push from PaliGemma's first plate contact?

Use the same 50 simulated Sawyer development layouts and the frozen Huber motor from the [contact replay](../embodiment-sawyer-source-contact-20261120-r1/RESULT.md). Restrict this diagnostic to development. Keep all forks and expert trajectories out of training.

At the end of the first control interval containing native hand-to-plate contact, compare two continuations from the same state. One replays the original frozen policy's issued controls. The other gives the remaining controls to a single fixed scripted Sawyer expert using available simulator state. The total budget is 300 controls including the prefix. Inspect the fork's physics, time and controller state, verify the raw replay against the archived trajectory, and retain rejection reasons. For teacher qualification, run the same expert from reset on all 50 layouts with 300 controls. Choose its route and handoff convention using existing source-training evidence before testing.

The primary result is expert rescues among the 30 raw failures. Report losses among the 20 raw successes, overall paired change, and whether the reset expert solves each layout. If the expert rescues many failures while retaining successes, the post-contact action sequence is a plausible target for corrective demonstrations on separate training layouts. If the expert succeeds from reset but repeatedly fails from contact on the same layouts, investigate the inherited state, remaining horizon, and ability of the expert to resume. Poor reset performance limits the interpretation of a null handoff. These alternatives need no target-arm data. Record all three branch outcomes per start, actual budgets and native rewards. This task uses CPU simulation only.
