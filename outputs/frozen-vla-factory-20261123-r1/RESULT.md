# Choosing an adapter for a frozen VLA on a new robot arm

**Question.** Can motion observed on a new arm identify a correction that recovers native task successes and preserves working behaviors? The task policy and its weights stay fixed. A change in the commanded direction, image, gripper or reachable poses can produce superficially similar failures. The comparisons below intervene on one of these at a time.

**Candidate method.** A source model predicts how far the tool should move for a frozen policy command. A 15-control target trace estimates how this robot responds. At deployment, the adapter chooses a command whose predicted displacement matches the source movement, while penalizing departures from the frozen proposal. The source-shrunk 3D model uses measured metric end-effector position. A separate experiment tests whether adapting only the directions actually exercised in the trace improves over the ordinary ridge penalty. The existing SymMeta reader has a different information budget. It reads motion from fixed-camera video without seeing horizontal command values, then aligns the inferred motion with commands. This supplies a direction reference when the reported Cartesian displacement rotates with the command frame. Its established setting is planar command shifts. A change in camera orientation compromises that reference.

**What prior work already covers.** ReGround tracks the motion intended by a frozen VLA using robot-state calibration and target dynamics. Mirage addresses cross-arm appearance and control using source-robot rendering and motion tracking. A general claim to freezing the policy and wrapping it with an adapter would duplicate prior work. The question here is what a short, passive trace identifies on a new arm and whether applying that correction increases success on the same held-out starts. [ReGround](https://arxiv.org/abs/2611.20244) · [Mirage](https://robot-mirage.github.io/)

## Native arm transfer in simulation

The three-arm historical evaluation shares a Cartesian controller, parallel gripper and command convention. It changes the simulated arm itself. On one start per task, unadapted π₀.₅ scored 8/8 on UR5e and 6/8 on each of IIWA and Kinova3. Both arms missed the drawer-and-bowl and two-moka-pot tasks. New Kinova3 trials use two previously unscored layouts for those tasks and one previously working task. The predeclared IIWA and UR5e screen includes all eight identities. Paired rescues and regressions are reported separately. Neither historical nor fresh simulation success certifies hardware transfer.
