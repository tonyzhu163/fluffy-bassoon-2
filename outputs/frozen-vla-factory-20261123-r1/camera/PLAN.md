# Does one camera orientation correction transfer across command interfaces?

Use archived frozen π₀.₅ UR5e supports at `757a44cd4374833cad790852df8b87ddf412e638`. Keep the seed-41 SymMeta readout fixed. Its visual head uses before/after RGB motion and public vertical displacement, then aligns its output to issued commands. Here “image-only” means this existing reader without independent camera orientation information. The intervention changes only its final planar yaw estimate. Apply a unit-slope correction with a sign fixed by the archive's displayed roll and world-azimuth conventions. The earlier camera study already found view-dependent drift and verified exact quarter-turn pixel inversion. This experiment tests a post-readout correction, including an independent way to estimate the correction.

- **Known orientation.** For digital roll, add the signed applied image roll. For physical orbit, compute the world-vertical rotation from nominal and current camera-to-world matrices. Compare the same native yaw readout with zero correction and with the opposite sign. Upright is a paired baseline.
- **Estimated roll.** Each fixed mount gets one independently measured, 15-control calibration trajectory, the first nominal slot of the first archive task. Project its measured world TCP displacements (joint FK) through the frozen nominal Panda/Sawyer brightness-flow projection. Estimate one rotation from that trajectory's measured image motion into those predicted pixel directions using a planar least-squares alignment. Share the resulting angle across all evaluation cases in that mount. Estimate continuously, without using any numerical roll, target interface label, test FK, upright counterpart, or test-task calibration. This requires externally known calibration motion in the reference frame. It does not identify an arbitrary camera pose from an unreferenced support.
- **Evaluation.** Score eight compositional/continuous OOD transforms per task, with the calibration task entirely excluded from roll estimation comparisons (56 trajectories, seven tasks). Each target supplies the same three five-control chunks in all arms. Keep full-frame synthetic ±90° rolls separate from the 1.4× cropped synthetic 0°, ±15°, ±30° views. Also report the known-angle result on the full original 64 OOD supports. Rotate the choice of calibration donor across all eight nominal slots as a sensitivity check, each time holding its task out. No selection by score.
- **Physical orbit.** Score the eight archived, physically rerendered, held-chunk-mean trajectories across two tasks at 0°, ±30°. Use the matched fresh nominal replay for this panel. Test only known relative azimuth here.
- **Falsifier.** If adding independently known or estimated orientation fails to reduce paired wrapped command-yaw MAE on changed-camera cases, the corresponding correction lacks support for that perturbation. Check smaller angles and upright for damage from approximate equivariance or calibration bias. Average signs within episode and episodes within task. Resample whole tasks (20,000 bootstrap draws, seed 20261123) conditional on the fixed calibration donor. Show effects by task for the two-task orbit panel.

Local CPU only. No motor parameter updates, simulator launches or native retry evaluations. Reuse the committed traces and predictions from [the archive](../../symmeta-camera-command-20261123-r1/RESULT.md).
