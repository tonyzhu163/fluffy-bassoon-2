# Does reader disagreement identify useful fallbacks?

Baseline `757a44cd4374833cad790852df8b87ddf412e638`. CPU-only retrospective screen. The question is whether disagreement about the command correction identifies supports where a different executable reader wins often enough to improve paired native-outcome replay. A nonpositive held-task contrast with always using SymMeta seed 41 counts against this rule.

- Use the 384 archived BASE task–transform–panel pairs, each with one 15-control passive frozen-policy support (three chunks of five) at layout 11 and a separate query at layout 13. SymMeta is the existing Panda/Sawyer-trained visual reader. The motor and all reader weights stay frozen.
- Designate UR5e × π₀.₅ as the only labeled calibration panel. For each of eight held task identities, fit on the other seven tasks in that panel (84 cases). Score only the held task on IIWA × π₀.₅, Kinova3 × π₀.₅ and UR5e × π₀ (36 cases per fold). Calibration reuses labeled archived tasks and is not a zero-label source-training result. None of the three target panels supplies a calibration label. Exclude every transform of the held task even on the calibration arm.
- Use the three frozen SymMeta seeds' predicted yaw, gain and grip from the same support. The ambiguity score is the RMS Frobenius distance of seed 41's inverse command map from seeds 42 and 43 on unit x, y, z and gripper commands, before saturation. No true transform, task/shift name, oracle, support reward, query observation, proposal or reward enters the score. At deployment the primary fallback is the archive's passive analytic Horn–Schunck reader on that support.
- For each held task, choose the threshold maximizing paired calibration successes, allowing both always and never switching. Break ties toward fewer switches. As a prespecified secondary comparison, use the same threshold-fitting procedure with the medoid of the three frozen readers as the fallback. The medoid is the actually evaluated seed with minimum summed squared command-map distance, with ties resolved by seed order.
- Compare the selected archived binary query outcomes against fixed readers, an expected coverage-matched random switch within each panel, task and fallback identity, and the descriptive per-query best of the two available actions. Record coverage, wins/losses, 95% paired whole-task intervals retaining all arm/motor panels and shifts of each task, and OOD outcomes. Show coverage sensitivity at fixed upper tails of the seven calibration tasks' score distribution. Report the primary decision even if a secondary operating point scores better.
- Check key uniqueness, fold separation, support hashes and distinct support/query layouts against the committed qualification receipts. Fix routes before scoring target outcomes and audit route invariance to changing those outcomes. One archive replay per selected branch cannot measure a newly rolled-out policy, independent starts or probability calibration of task success. Stop after this CPU analysis.
