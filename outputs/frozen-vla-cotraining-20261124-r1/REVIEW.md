## What the original papers tested

- Yang, Finn and Sadigh jointly trained a π₀.₅ backbone and a context encoder with flow matching. Their WidowX data varied controller type and gain. Their query demo was disjoint from the expert context trajectories, which were collected under the deployment controller. This directly precedes joint policy/context training. Our question concerns what four transitions of the robot's own rollout can contribute after a single-source fit. [ICBA, §§IV–VI](https://arxiv.org/html/2610.39280v2)
- Mandlekar et al. found recurrent behavioral cloning effective on human demonstrations. Wen et al. showed how temporal action correlations allow a history model to copy an expert's preceding command and score well offline while missing action changes in closed loop. Both mechanisms are plausible on successful Panda tapes. Hsieh et al. reported 82.3% with history versus 80.3% with current observations when ranking two frozen VLA candidates on four LIBERO tasks, using terminal-outcome supervision. The proposed model instead changes the generated action field with demonstration labels. [Offline human demonstrations, §4](https://proceedings.mlr.press/v164/mandlekar22a/mandlekar22a.pdf) · [Keyframe-Focused Visual Imitation Learning, §3](https://proceedings.mlr.press/v139/wen21d/wen21d.pdf) · [History-conditioned verifier, §IV](https://arxiv.org/html/2611.14834v1)
- Ebert et al. co-trained on bridge data **and 50 target demonstrations**. Physical Intelligence's π₀.₅ combined heterogeneous robots, language/vision examples and semantic tasks. Here “joint” refers to updating two parameter blocks under one source demonstration objective. OpenVLA's rank-32 LoRA reached 68.2% versus 69.7% for full fine-tuning in its Franka comparison. Its last-layer-only variant reached 30.3%. Those results motivate an empirical test of which weights to change. OpenVLA's LoRA covered a different architecture and more parameters than one π₀.₅ output matrix. [Bridge Data](https://arxiv.org/abs/2109.13396) · [π₀.₅, §§IV–V](https://arxiv.org/html/2504.16054v1) · [OpenVLA, §5.3 and Table 1](https://arxiv.org/html/2406.09246v3)

## Which weights and inputs reach the robot?

I traced the worker's output-layer code at `fd661874` against OpenPI `215abfb2`. In policy-only and joint, `install` sets the trace-local native `Pi0.action_out_proj.kernel` to the deployed-dtype value of `W + left @ right` (rank four). The stock sampler calls that layer **inside each denoising step**. Adapter-only retains the stock kernel. In adapter-only and joint, a bias-free 52→16→320 branch adds a history-dependent velocity to the ten 32-coordinate outputs. Its offset is fixed across flow times within that query. The transformer, vision tower and output bias have no fitted update. The checkpoint files hold factors separately and the bound JAX call reconstructs the effective kernel. Thus the implementation can change a real stock projection while preserving the distributed base checkpoint. The worker's Baige CPU receipt shows a 1,024×32 restored kernel changed after one synthetic gradient step, with exact zero-update parity. The policy and history factors contain 4,224 and 5,952 trainable scalars respectively, giving 10,176 in joint. Fitted weight changes and real rollout effects require receipts from the actual fit. ## Shortest test that changes the decision

First use the locked source holdout and one already qualified source observation. Reconstruct the prefix, reproduce stock with no update, verify effective weight changes and cache equivalence, then compare aligned/zero/lagged proposals on the identical input and noise after a real five-control prefix. Include a last-command predictor at action changes and the jaw/command control above. If the intervention never reaches an issued coordinate, diagnose that path before scoring more episodes. This screen can establish mechanical sensitivity at low cost.

The shortest registered native test of arm transfer on **familiar tasks** is the supplemental 40-episode crossing with one Object and one Spatial fitting instruction, two starts per task, both arms, the four factorial cells and joint-zero. Keep task and row fixed when comparing each within-arm treatment effect. This isolates the arm switch at fixed instruction, with four task–layout pairs. Report the set of possible reused source placements if the release-to-demo identity cannot be reconstructed. Its zero control addresses any benefit of giving the branch input and leaves timely-response attribution open. [Matched-task registration](matched-task/PLAN.md)

For transfer to **tasks withheld from this fit**, the parent protocol registers 108 episodes on three tasks from libero_goal and libero_10. Its six modes include one-replan lag. Retain all starts and the matched Panda subset, including ties and regressions. A ceiling for stock leaves no observed rescue opportunity. Equal or lower reward against the best single component, or aligned history tying displaced history, weakens the corresponding claim even if imitation improves. A null in this panel combines the new task distribution and new arm. The two native panels answer different questions. [Parent panel](evaluation/PANEL.md)

Fitting only on Panda leaves the policy response to new arm dynamics unconstrained. Phase, recent command persistence, human teleoperation style, contact and current jaw width can all predict the next Panda action. For a **body-specific** follow-up, cross the same task, reset and safe command prefix on two source dynamics, vary realized response independently of action/appearance as far as the simulator allows, and obtain independent successful expert continuations on each source body. On fixed query observations swap only those matched responses, then test the predicted corrective direction and paired native reward. It cannot reveal which different command an expert would choose after a Sawyer-specific deviation. Keep Kinova3 sealed for evaluation.
