# Kinova3 plate history audit

Both adapters changed the **sixth issued control on all 64 layouts**, at identical pre-action physics, observations, history and noise. Both steered more in +x, −y and −z. The first changed control already moved the tool lower and farther in −y than stock. The stock trajectories subsequently moved the plate toward the goal, while the fitted trajectories made little or negative progress by 100 controls. The audit found matching label, history, flow-integration and execution conventions. The source fit rewarded copying a privileged teacher on its own trajectories. Preserving stock's successful approach from stock-generated Kinova3 histories was outside that objective. [Per-layout evidence](evidence/readback.json)

## Source fit and execution contract

- **Labels and order.** The Paddle teacher used object and goal geometry, gripper collision mesh, phase and an integrator. All 4,189 commands in 40 native replays matched the archived teacher arrays, and all source replays earned native reward. Across 512 packed rows, including repeated diagnostic rows, every action target was the actual issued slice `a[t:t+10]` at the corresponding pre-action proprioception. Source and target used the same relative OSC convention at 20 Hz, with three world-frame translation coordinates, three rotation-vector coordinates and one PandaGripper command. Native goal scales were 0.05 m and 0.5 rad per axis at unit command. - **Causal history.** Both paths use the last four completed transitions, oldest first, zero-padded on the left. Each slot stores the seven issued controls, measured tool XYZ change, finger separation change, current separation and validity. Only the five metric inputs are multiplied by 100. The replay reconstructed all source histories and all target replan histories from the saved actions and bracketing states. The frozen policy also sees both physical finger positions separately. Source windows start at arbitrary controls and include partially populated histories. Target replans every five controls and first uses a full buffer at zero-based `t=5`. - **Frozen model and decoding.** The original checkpoint's restored bfloat16 output kernel is byte-identical to the deployed kernel. The checkpoint manifest, action normalizer and both real head exports match the fit seal and the evaluation's frozen parameter receipts. Full checkpoint hashes and the full camera and HDF5 fingerprints come from the sealed fit and native readbacks. Source and target use the same `pi05_libero` transforms with quantile normalization and the extra delta transform disabled. The seven action decode slopes are `[0.8423, 0.8278, 0.9373, 0.1280, 0.1752, 0.2530, 0.9998]` in command units per normalized unit. ## What the mismatch supports

The teacher's opening had mean commands near `[+1, −1, −1, −0.58, +0.65, +0.90, +1]`. Every teacher command closed the gripper, making its history coordinate identical to the validity bit on source. All 256 valid gripper history slots at the matched target replan instead held negative commands. Both real heads still produced a strong direct −y/−z correction on those histories. In an offline head-only check, replacing just the four gripper history fields with +1 changed the median maximum direct decoded component over the first five rows by 0.037 for Panda-only and 0.018 for mixed. The alias is real and the tested feature change accounts for a small part of the direct correction. The source and target also differ in what the history records about the approach and arm response.

Gripper sign matched stock in all five rows issued at the first adapted replan. Later, 63 Panda-only and 64 mixed layouts issued close commands, versus zero stock layouts. These observations support an early shift toward the teacher's approach before any gripper direction change, followed by poor progress on the target trajectories. Which coordinate, contact or embodiment effect drove terminal failure remains unresolved.
