# Can the native gripper account for cross-arm transfer?

Use the published LIBERO-Pro2 BASE physics, stock arm models with the benchmark's mounted gripper, robosuite 1.4.0 and MuJoCo 3.2.3. The question is whether a deployable change to the seventh π0.5 action or a fixed tool calibration can compensate for an actual difference between the source and held-out arms. The policy, preprocessing and weights stay frozen. No transfer outcomes, reference object poses or teacher commands enter fitting.

1. Read the original nominal source supports (24 train tasks, layouts 0–3, Panda/Sawyer) and nominal target supports (eight official tasks, layout 11 on each held-out arm). Count observable onset/closure separately in passive π0.5 and deliberately excited active probes. The archive records five-control means and endpoint jaw measurements. A five-command mean strictly below −4/5 proves all five inputs negative under the recorded bounds. We cannot recover arbitrary within-chunk timing. Report both directions of motion and paired active endpoints, without treating replicated near-identical traces as independent.
2. Compile all five robots in the native drawer-and-bowl case (libero_goal/3, layout 11, historical support seed). Run matched magnitude 1 and 1/8 close–hold–open pulses from identical resets with stationary arm commands. Read the actual format calls, actuator controls, finger slides, pad geometry and contacts. Compare fingertip displacement and measured closure timing at 20 Hz. Any same-sign magnitude effect or different actuator law contradicts common transduction. If all bodies share hardware and command response, do not fit an arm-specific onset predictor.
3. Compare geometry at equal jaw coordinates using the compiled transforms. Predict midpoint of the two opposed pads from the measured grip site using identity versus the Panda tool-frame pad offset. Separate the common origin convention from the correction required *relative to Panda*. Test on a previously recorded complete frozen Panda π0.5 BASE trajectory, libero_10/3, layout 1, putting a bowl in a drawer and closing it. Chosen as a staged drawer grasp from the prior TCP study before reading alternate-arm outcomes. Replay the same commands for all arms. Check the source native outcome, grip-site positions, and reward sequence against the archive first. Measure actual pad-to-object alignment, TCP versus pad-center tracking error at the first close, contacts and native reward. Each replay is a fixed-command diagnostic. A constant offset that is the same on each arm supplies no basis for an arm-specific action correction; target-dependent approach or contact errors instead motivate a local grasp comparison.
4. A fresh policy GPU comparison requires a nonidentity intervention with an evidential basis on source only and a qualified executable interface. Stop at a measured mechanistic null if the proposed corrections reduce to identity. Nominal counts, raw source and target measures, and any qualification discrepancy remain in this directory.

Budget is one Baige CPU process restricted to two cores and zero scheduler submissions. Use the local arm runner pinned in Git, the installed simulator, project shared storage and CPU Mesa. The object, contact, actuator and FK readbacks are privileged evaluation diagnostics. Public deployment channels would be the policy proposal, public EEF pose and two finger encoders.
