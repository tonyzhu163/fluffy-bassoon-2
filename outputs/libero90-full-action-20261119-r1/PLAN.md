# An ordinary practice attempt and action selection on standard LIBERO-90

Does an outcome-trained history reader attached to frozen π0.5 improve native retry success on held-out tasks? Is any improvement attributable to the previous attempt, and does it exceed memory-enabled imitation at the same deployment budget?

## Actions and data

Use the frozen JAX pi05_libero checkpoint, standard nominal LIBERO-90, the native five-step replan cadence and 400-control horizon after ten settling actions. Run one ordinary π0.5 practice at a distinct pose on the same task for every comparison. Every five controls on the retry, draw two complete ten-by-seven action proposals from the same frozen policy. The attachment scores the proposals using the current public features and the practice. Execute the first five commands of its preferred proposal and replan on the resulting observations. This permits different translations, rotations and gripper commands at every replan. The frozen motor defines the support of the action distribution. The learned attachment selects among native samples and does not synthesize arbitrary action vectors.

Train on 48 tasks with 20 independent practice/query pose pairs per task. On each query start, collect two ordinary stochastic continuations with different policy randomness and the same environment seed. At each replan, an independent coin chooses which candidate to execute. Treat the other candidate as unlabeled. Both continuations share one practice, and their outcomes are noisy measurements of whole trajectories. Use the 12-task development split for runtime and behavior analysis. Freeze both methods before opening the 30-task test, 24 fresh paired starts each. The benchmark and split hold out tasks from reader fitting. There is no guarantee the motor never saw these tasks. [Fixed task/reset catalogue](../libero90-meta-retry-20261119-r1/cases.json)

The outcome reader learns the probability of terminal native success from the chosen chunk, actual history and current observation under the collecting policy. The imitation reader learns to repeat successful chosen chunks relative to other available proposals using categorical imitation. Both use the same architecture, ordinary practice histories, actions, trial archive, update budget and three model seeds. Retain successful and failed practices. Train intact and cleared forms; estimate per-case outcomes for one frozen three-seed ensemble per method. Training on the return of the whole trajectory gives a noisy signal about each individual decision. Verification requires each policy's live closed-loop evaluation.

## Fixed comparisons

Score all 720 test cases and average native second-attempt success equally across the 30 task IDs. Use the same public initial observation, simulator state, initial practice, horizon and policy-randomness schedule per case in every arm. Future observations diverge when actions diverge. A single-draw base executes the first candidate. Computing a spare sample and discarding it gives a compute-matched base with the same actions if the noise stream and model state are independent. Verify that equivalence in qualification. Report compute per decision, environment controls, support success, query success, and probability of at least one success across both attempts.

Predeclare three ordered comparisons of the outcome-trained policy: (1) intact versus native base; (2) intact versus the same weights with memory cleared; (3) intact versus memory-enabled imitation with access to the same factual practice. For each, average paired binary differences per task, then report the mean and a two-sided Student 95% interval across task means (29 degrees of freedom). Use the ordered tests at 5% in a fixed sequence. Report all estimates even if an earlier comparison fails. Also report imitation intact versus cleared, the difference between recipes in their history gains, paired rescues and regressions, and per-task differences as descriptive analyses. A shared persistent task identity is present across resets. Attribution to specific failure feedback would require a further controlled history intervention. Five percentage points is the planning effect. A positive interval against base alone establishes a system gain. The task-count and power assumptions are in the [registered sample-size calculation](../libero90-meta-retry-20261119-r1/PLAN.md).

Fitting costs 2,880 simulator episodes. Evaluating each case with one shared practice and six live retries (native base, a compute-matched base and both readers intact and cleared) costs 1,008 development episodes and 5,040 test episodes. The live comparisons and fitting together cost 8,928 episodes. If the full development logging panel is also collected, include its 432 additional episodes in the ledger. Additional qualification, if needed, is charged separately. Use Baige Distributed Training for full runs. Budget up to 50 incremental GPU-hours for this comparison. Estimate time from actual accelerator rollouts before consuming the reserved test. If the complete comparison requires a higher budget, report the measured rate and request the difference. Preserve the registered test size and endpoints.

With uniform randomized action logging, successful actions have density proportional to the native proposal density times their success probability conditional on the context. An ideal success-conditioned imitation classifier and an ideal outcome scorer can therefore prefer the same action. The comparison tests whether negative outcomes and this objective improve finite-data action selection or history use on live rollouts. It does not assume an intrinsic advantage for the outcome objective.
