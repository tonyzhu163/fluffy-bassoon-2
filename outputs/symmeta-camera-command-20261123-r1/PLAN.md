# Does the frozen SymMeta reader separate camera roll from command yaw?

On held-out UR5e, cross the twelve existing command-interface transforms with adapter camera rolls of 0°, +90° and −90°. Use all eight official tasks and the same archived passive π₀.₅ trajectory in each view. This is an exploratory offline test of a frozen estimator. A camera-robust reader should retain its yaw accuracy when only the adapter view changes. A large paired change in the predicted yaw, with accurate control estimates from independent motion measurements, counts against this hypothesis.

Use the first 15 issued controls (three five-control chunks). Rotate the full square RGB arrays by exact quarter turns about their centers, including frame zero. Angle signs denote counterclockwise displayed image rotation. This intervention tests optical-axis roll with no interpolation, disocclusion or change to the policy, dynamics, commands, proprioception or true command yaw. It does not test camera orbit/translation or rerun task success. A prior physical-roll audit established that static images expose roll, but did not test this reader on motion. Released Pro2 S15 perturbs the policy views as well. [Prior physical-roll audit](../libero-xemb-camera-20261119-r1/RESULT.md) · [Prior S15 control](../xemb-camera-dev-20261122-r1/RESULT.md)
