# Critical review of the cross-arm pilot

Static review of the integrated driver, including the change that makes poor calibration scores diagnostic. The local execution record covers factory preflight. Completion still requires the two source-fit records, the saved checkpoint and all four paired UR5e cases (20 native episodes).

1. **Hard execution dependency — the optional UR5e teacher can still cancel both source fits.** The driver constructs it before pretraining. A rank-deficient measured UR5e response raises even with a full-rank command design and a damped inverse. Move target calibration after the source checkpoint. Report identifiable directions and use the damped solution where defined. If the oracle is unusable, score the four other controllers and mark the oracle unavailable. Preserve hard failures for invalid simulator state or broken query pairing. [Driver](pilot.py#L267) · [Rank check and inverse](learner.py#L76)

2. **Teacher validity — the forward check does not measure the benefit of the inverse.** Beating constant drift on a fresh probe can coexist with a clipped correction that increases motion error on policy commands. Panda’s self-teacher is identity by construction. On fresh matched Sawyer starts, compare measured motion under original and corrected proposals against the same Panda reference, separating translation and rotation and reporting clipping. Treat this as a diagnostic alongside native success. Four UR5e starts measure this controller on this panel and cannot establish a reachability ceiling. [Forward check](pilot.py#L227) · [Teacher](learner.py#L96)

3. **Pairing and gradient validity — support commands can identify training pairs.** Each proposal bank receives both body labels, but each label independently draws one fixed practice episode. With four joint-practice tapes per body, the command sequence itself can correlate with the label. Use the same practice task, reset and commands for both labels of each bank. Both optimizers include the reader. The zero-initialized residual head blocks its first joint gradient, and finite parameter-change reports can still be zero. Read back both stages’ reader/head changes and teacher-minus-proposal magnitudes. Describe a zero update as such. Final UR5e outcomes cannot isolate the contribution of pretraining. [Practice pairing](learner.py#L187) · [Gradient and fit audit](learner.py#L218) · [Shared proposal banks](pilot.py#L305)

4. **Runtime evidence — the matched query checks establish repeatability within this driver.** All five conditions share its motor conversion, so a common input or action error can pass the opening-proposal check. Use the released-adapter Panda parity check on Linux and compare one matched frozen Panda opening against the qualified motor, including transformed views, 8D state and issued action prefix. Retain exact within-UR5e reset, noise and opening checks for the native comparison.
