# Native cross-arm transfer with a frozen π0.5

Does a correction calibrated solely from movement on one target start improve native task success on unseen starts of a real alternate simulated arm? A lower error predicting free-space displacement can coexist with no task gain, and intervention can spoil already successful starts. A second question is whether a privileged feasible Panda trajectory can drive Kinova3 to the same terminal reward. The target policy always runs closed loop in the raw and adapted conditions. The privileged tracker is a separate feasibility diagnostic conditional on Panda success.

- Use released BASE tasks and actual Panda and Kinova3 MJCF. Share their world-frame relative OSC_POSE interface, 20 Hz control, two-finger Panda gripper and camera placement conventions. The arms differ in their link geometry, masses, kinematics and rendered appearance. No synthetic coordinate transform is applied.
- Use fresh panel layouts 14 and 15 for the drawer-and-bowl task (libero_goal/3), two moka pots onto the stove (libero_10/8), and cream cheese onto the bowl (libero_goal/6). They were chosen using prior layout 13 results, so this pilot estimates transfer conditional on that selection. The first two failed for the raw Kinova3 and IIWA on layout 13, while the third succeeded. The frozen VLA is the existing LIBERO-finetuned checkpoint. Task and object novelty for that model is unverified. Held-out physical arm and adapter-training split are the relevant claims.
- Shared within each pair are the exact released scene, instruction, flow-noise bank, controller contract, native horizon and seed. Across arms initial arm images, joint poses and physical states differ. Within Kinova3 require the same physical reset, raw public observation hashes, noise and initial frozen action for every action reader. Use stock OpenPI input preprocessing with the historical π0.5 quaternion convention and replan every five controls. Source and target have distinct live observations.
- Query outcomes and task rewards cannot fit the reader. Both matrix controls use the same separately recorded 15 target controls from start 11, the named source fit and its digest. Report no correction, a planar correction, and a full three-dimensional correction. Translation alone changes. The only geometry oracle for the *imposed* command shift is the identity on all these queries.
- Separately test a privileged full pose tracker only when the source query succeeds. It replays the successful source's normalized commands and adds closed-loop errors in measured world XYZ and orientation, bounded by the physical OSC scales. Source orientation is interpolated across five-control chunks. After source success it holds the final pose and gripper through target native termination. During tracking the simulator supplies target robot state, and the reference is a solution for that exact query. Its success establishes task feasibility along this trajectory. Its failure does not establish physical impossibility.
- Score native simulator success, native reward tape and controls to termination. Report paired gains and losses, disagreements by task, and omit tracker comparisons with a failed source. Each layout receives one noise draw. Trials on the same task are dependent. No architecture wins on movement-prediction error alone.
