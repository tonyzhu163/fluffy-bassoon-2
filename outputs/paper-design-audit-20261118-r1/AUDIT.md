# Can a frozen robot policy use one attempt to improve the next?

Design audit, 18 November 2026. Repository reviewed at `796eb203`. The published benchmark files were inspected statically at LIBERO-Pro2.0 `e5500c69`. The experiments below are recommendations.

**Use LIBERO-Pro2.0 for the main transfer experiment and RoboCasa365 OpenDrawer for the mechanism control.** The paper should ask whether experience from one manipulation changes the robot's next decision in a way that improves native success on a fresh reset of a held-out task. A timing shift is a good first test because the instruction can stay fixed and the robot can observe how its commands played out. Whether that information changes which feasible action succeeds is an empirical question.

## What LIBERO-Pro2.0 actually offers

The release holds out eight of 40 base task IDs across four suites. The project's 24 fitting and eight development IDs partition the other 32. Keep every descendant of a base task in its split. Object tasks repeatedly place different groceries in the same basket, and Spatial tasks repeatedly place a black bowl on a plate. Report task-ID holdout from the history learner and give per-suite results. The selected π0.5 is LIBERO-SFT and its exposure prevents an assumption of backbone novelty. Keep the official independent-episode score separate from the project's repeated-attempt protocol. ## The next experiment

1. **Run the prepared eight development episodes.** Spatial 1 and Goal 1 each get BASE, zero-adapter BASE, S15 and S20. Verify native competence, paired resets, the complete action path, native rewards, physical controls, seconds and storage. The existing qualifier saves one public state per ten-command chunk. For the timing pilot, also record control-rate public proprioception and issued commands through the final support transition. This lets a simple reference estimate lag and exposes information lost by chunk summaries. Keep internal delayed commands and the condition label evaluator-only. [Qualification code](../libero-meta-learning-20261117-r1/qualify.py)
2. **Find out whether knowing the condition changes the best action.** On development, cross BASE/S20 with the same scenes and noise. Execute a small set of attainable responses, for example the native motor and a version with a conservative approach speed near closure under the same control budget. Use a public trigger. Learn the best fixed choice and a condition-given choice on separate fitting cases, then score both on fresh cases. Repeat candidate continuations under fresh noise to avoid treating a lucky successful branch as an expert. If one fixed correction gets the entire gain, report it and move on to a different mechanism. A condition classifier alone cannot answer this question.
3. **Separate the reader from the motor.** Compare a public command–motion lag estimator plus the same candidate selector, a small learned history reader, and a current-episode-only reader. Then give the *actual learned motor interface* the true condition on development and measure native success. If the history reader succeeds but the condition-given adapter cannot execute useful actions, work on the adapter or evaluate the selector under its own name. If the privileged policy works but the public reader fails, investigate missing observations, state sampling and the history target. Only then is a bigger transformer fit informative.
4. **Fit one DPT-style policy first.** Construct support/query pairs with a shared condition, independent resets, failures retained, and the same public information available at deployment. A competent condition-aware teacher or measured simulator branches can label the exact training query. A memoryless teacher presented with the identical observation and noise supplies the same action under both hidden conditions. Such labels give the model no reason to learn the distinction. Match the memoryless fit on states, teacher labels, action interface and optimization budget. Use a same-label training ablation that permutes support across conditions if attributing improvement to the corpus construction. A chronological AD/VLRLA-style comparison tests the existing alternative; that comparison needs genuine improving source histories. DIT and IC-IQL remain secondary until their scores rank physically measured competing actions within the *same* history. [DPT](https://proceedings.neurips.cc/paper_files/paper/2023/hash/8644b61a9bc87bf7844750a015feb600-Abstract.html) · [Algorithm Distillation](https://arxiv.org/abs/2210.14215) · [Local method contracts](../../docs/METHODS.md)
5. **Scale on development, then lock the test.** Use the existing nested 8/16/24-task subsets at equal total source trials and optimizer updates. Vary independent trials per task separately at fixed breadth. Track distinct decision states and native successes/failures per task and condition. Preserve complete trial/teacher streams across splits. Reserve compute for paired evaluation and independent fits before bulk collection. Use measured episode time, storage, paired discordances and a decision-relevant effect size to set the final case count. The last campaign record reports 2.36 of 200 GPU-hours charged and access interrupted before LIBERO GPU qualification. [Scale plan](../libero-meta-learning-20261117-r1/PLAN.md) · [Execution record](../libero-meta-learning-20261117-r1/EXECUTION.md)

## What belongs in the paper

**Primary figure.** On each of the eight held-out base tasks, collect a common frozen-SFT support attempt, carry the same condition to a fresh query reset, and compare attempt-two native success for the *same frozen student* with relevant versus cleared prior-episode history. Preserve the entire current-episode prefix in both arms. Pair initial states, policy noise, event randomness and available physical controls. Include every predeclared valid case regardless of support success. Macro-average over tasks and prespecified conditions, show discordant wins/losses and paired intervals, preserve shared donor/trial blocks, and display each independent fit. Eight tasks limit the breadth of inference. The three source documents differ in their headline contrasts. Predeclare retained-minus-cleared as primary and relevant-minus-different-condition as the specificity check. [Research question](../../docs/PAPER.md) · [Constructed-history proposal](https://github.com/tonyzhu163/fluffy-bassoon-2/blob/409baf7aca4c52959da72d55edd38c5f028b65c9/fable.md) · [LIBERO protocol](../libero-meta-learning-20261117-r1/PLAN.md)

**Controls that determine the wording.** A fresh donor from the **same condition** can work as well as the original support if either reveals the lag. A same-task donor from the **other condition** tests specificity. In a binary study it is deliberately contradictory, so a large effect against that donor alone is weak evidence of utility. Use comparable support outcomes and lengths where feasible, select donors independently of query outcomes and disclose coverage. Add an independently reassigned query condition as a null for useful persistence. Report absolute success alongside the trained current-only model, frozen SFT, a fixed source PPO if qualified, and the simple condition estimator. Repeat with the selected learner **generating its own** support through three attempts, with a fully cleared retry policy at the same budget. Only the latter panel licenses the own-experience claim. Plot marginal success by attempt and show cumulative success separately.

**Reward and novelty.** If motion alone delivers the gain, describe cross-episode dynamics adaptation. To claim reward-dependent learning, hold public observations/actions fixed and intervene on prior feedback in a task with plausible alternative feedback, then compare native query outcomes. Check success termination, duration and visual cues, and include a reward-blind trained model. Active exploration would require showing that the learner's chosen support actions improve later return against matched passive or fixed probes, including the cost of probing. VLRLA already studies deployment-time reward histories, context length and history transfer. RoboHarness already uses memory and interventions around a frozen VLA on LIBERO-PRO. The contribution available here is a controlled account of which prior experiences improve *attainable physical actions* on held-out tasks, with a matched training-data intervention if claiming a new recipe. [VLRLA, §§4–6](https://arxiv.org/html/2610.19517v1) · [RoboHarness](https://arxiv.org/abs/2603.24060v3)

If reward-driven RL is central to the submission, pair the timing study with a separately labeled hidden-goal test. Give the same ambiguous instruction in a scene with two valid destinations. Keep the rewarded destination fixed across attempts and randomize it across trials. Score the same completed probe against each destination's simulator predicate so the visible motion is identical and its binary feedback differs. Deliver the feedback at the same public boundary. On a fresh layout, execute the frozen student's placement and score it against the assigned predicate. First establish that the condition-given student can place at either destination. This last check was exactly where the compact-bowl experiment fell short. [Bowl qualification and learned-carry results](../robocasa-bowl-dpt-labels-20261110-r1/RESULT.md)

**Publication decision.** If one algorithm wins the matched and autonomous comparisons across held-out tasks and mechanisms, lead with the size, cost and limits of that effect. If the public lag estimator matches the learned policy, report what the simple baseline explains. If the qualified motor and informative support still yield a precisely small effect, the existing RoboCasa results plus an independent LIBERO result support a paper about when cross-episode learning fails to improve control. Wide intervals, a weak motor or an uninformative mechanism leave that conclusion open.
