# Development-only grasp continuation

As a check on the meaning of a motor failure, take the left-prompt trace on each development scene. Replay its actual commands on Linux CPU, checking every public state against the accelerator trace, stopping at the first native finger grasp. From this identical grasp run two separately simulated continuations: one to each bowl, using privileged fruit and bowl coordinates and a single fixed, nonlearned raise/carry/lower/open/retreat controller. Keep the full 500-control cap including the VLA prefix. Missing grasps are failures for both continuations. Record first released side, prefix length and phase diagnostics. This check can isolate post-grasp control and demonstrate physical reach; a successful oracle-assisted placement cannot qualify the frozen motor or open the reserved scenes. Do not use the outcomes to tune this controller.
