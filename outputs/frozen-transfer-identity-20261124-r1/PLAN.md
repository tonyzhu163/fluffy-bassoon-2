# Does the frozen policy carry a different object on native transfer failures?

Registered November 24, 2026, after the wrist-retention study and before reading any endpoint object identities or identity counts. Exploratory reuse of an existing panel. No target labels used to choose these rules. The parent supplies the scoring pin through identity-pin. Work uses Baige CPU 32,33 and zero GPU-hours.

## Prior evidence and decision

RAM uses the instruction to retrieve a demonstration and transfer its interaction affordance into the new scene. Im2Flow2Act predicts instruction-conditioned object flow and uses a policy trained on simulated play to execute it. These methods ground desired interactions. Neither reports how often this frozen π₀.₅ physically carries a different item in native LIBERO-Pro2.0 transfer. [RAM](https://proceedings.mlr.press/v270/kuang25a.html) · [Im2Flow2Act](https://proceedings.mlr.press/v270/xu25a.html)

The wrist study found aperture already distinguished the matched carried/empty examples. All native arms share the simulated jaw model, and the gripper study found that where the pads arrive can change even for identical grasp commands. A camera phase reader detected the first drawer opening, which sometimes reversed. On a separate known Kinova3 drawer layout 15 tape the CPU replay first touched the plate at control 67, with no earlier drawer contact. Layout 14 instead opened the drawer and kept interacting with it. Those are evidence for approach or phase errors, with different tapes from the primary Kinova panel here. The present question is whether a post-closure identity reader would encounter a *loaded wrong item* on failed native tasks. Positive evidence could motivate a source-trained reader if independent matched loads exist. No observed strict wrong carry on a failed original tape ends this screen. ## Task and observation rules

[Released task table](tasks.json) contains the native instruction, initial placements, goal predicates, objects, fixtures and hashes, independently extracted from the eight BASE releases. For pickup identity use the placed object's instance in each In or On goal. Resolve spatial references using the released initial assignment. Keep both moka pots eligible in either order throughout. Revisiting an already placed pot could be a phase error; identity alone cannot decide. A plate, basket, bowl, stove, drawer or caddy that receives a target is a receiver; the object-of-interest list and every named noun are insufficient to select the payload. The target for both spatial instructions is bowl 1; bowl 2 is same-category but has a different initial spatial relation. Flag any conflict between the public referent and released instance, unmapped root or insufficient instance specificity. A private object name gives the predicate's identity; it need not be recoverable visually from a wrist crop.

1. Score every saved preterminal five-control window where every issued jaw command was positive. Reconstruct the strict physical test independently from finger contacts, unsupported status and released free-object roster; cross-check the archive's carry and empty labels. An exact instance or its native rigid root with the suffix `_main` maps to that instance. Handle names of fixture components by their declared parent prefix for contact summaries only. Preserve unrecognized labels as unresolved. Do not guess from a similar word, category, side, window majority, native reward or the final position.
2. Strict correct/wrong requires exactly one identified free object carried by both fingers, with no external support, at every sampled endpoint and no different carried identity at any of the five. A recognized loose non-target, including a loose receiver if carried, is wrong. Distinguish same-class distractors, other distractors and receivers. Merely touching a receiver, distractor, support or fixture while carrying a single object leaves that carried identity intact; report concurrent touches explicitly. Multiple carried objects, switching identity and unknown carried identities are ambiguous for this comparison. Partial or supported grasps, one-sided touch, palm-only contact and fixture manipulation give no five-endpoint payload identity. Record those, genuinely empty windows, and any shorter wrong carry evidence separately. Approach intent, pre-closure, brief events between endpoints, terminal/partially closed windows and any unsaved actions are outside the observed label. A strict carry is a sampled unsupported grasp, without an extra displacement or duration criterion.
3. Primary population is the 22 original target-arm/raw-command/original-layout replays. Attach the original rollout's native success/failure to the *same tape* and also report realized replay success, truncation/censoring and agreement. Count each episode once for any strict wrong event irrespective of repeated windows. Compare its intersection with native failures to all actual native failures; also count among successes, among failures with a documented load, and on same-outcome replays. Keep all episodes, including zero eligible windows. Break down counts by task and arm. Identify tasks having a possible non-target free payload, separately from tasks containing only legitimate free payloads.
4. Keep changed-layout target replays (22, same commands), swapped-arm replays (8, IIWA commands on UR5e), Panda original and alternative-layout source replays separate. They cannot enlarge the native failure denominator. Only compare physical alternatives within exact donor hash, task, common control, and applicable matching conditions (same arm for layout change; same starting scene and layout for arm swap). Require unambiguous loaded correct vs loaded wrong in these actual matched windows. Never pair arbitrary failures and successes, or select artificial negatives from empty closures or renamed instructions.
5. Report numerator and denominator, task heterogeneity and coverage. Resample whole tasks with all their arms, starts and paired event/outcome indicators together for a descriptive 95% percentile interval on observed wrong exposure per failed tape when it varies. A zero-event bootstrap is degenerate. Report counts of affected tasks among tasks with failures and a conditional one-sided 95% exact zero-event reference for that *task* unit under an independent exchangeable-task model, with its assumptions. No iid-window inference, causal rescue extrapolation or population ceiling from these selected cases.
6. If some naturally failed episodes carry a strict wrong object, check for both source classes outside each held task and for usable matched correct/wrong grasp examples in the held panel, including comparable phase and aperture. Fit only with independent source evidence. Conditional smallest proxy uses public instruction and causal camera frames with fixed source retrieval or image descriptors, identical aperture/close-age/time comparator and source-only selection. Score held-out tasks and arms with trials grouped and target labels reserved for readout. Document a missing comparison if these requirements fail. Do not manufacture matches, interchange task IDs as instruction features, or derive reader inputs from private labels. If natural failures have no strict wrong pickup, stop before any model. The present analysis is retrospective even with these pre-readout rules.
