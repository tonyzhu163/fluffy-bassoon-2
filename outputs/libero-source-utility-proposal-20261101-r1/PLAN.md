## Three alternatives, not prerequisites

**A — Paired teacher competence and improvement.** On a prospectively bound fresh SOURCE bank covering every source goal, compare raw native/full-H Gaussian and actual warmup/tied Gaussian controls with the initialized SAC actor and the preselected final TRAIN actor. Compare initialized and final actors in the **same** mode: deterministic mean if assessing DPT labels; stochastic sample separately if assessing the actual behavior policy. Do not treat Gaussian→bounded-SAC distribution changes as learned improvement. Pair initial states, instructions and query RNG in a common runtime, with measured post-settle identity; retain every failure and regression. Report paired outcomes/steps/action cost by goal and aggregate. A competent ceiling teacher is valid for DPT even without positive binary-success gain. No positive-gain requirement for every task and no task/lineage filtering follows.

This option asks whether the exact label/behavior teacher works. It does not test a history controller. An “initialized actor” must bind its actual original initial state/seed/config/checkpoint before its first update, not a retrospectively guessed identity. If that original state is absent for an archived teacher, report the missing comparison; its final-vs-native panel can still measure competence without being called an initial→final learning curve. A new initial-state capture would be a separately adopted choice.

**B — Learning histories versus stationary retries.** Compare prospective actual ordinary-SAC learning histories with separately recorded stationary initialized/final-policy histories on the same fresh source-case population. Keep all warmup, unsuccessful, flat and regressing episodes. Report behavior content hashes and pre-action/pre-SGD/post-SGD clocks alongside first-versus-later success, actual rewards, duration and failure→later-success counts. Match stochastic seed schedules and whole-episode interaction envelopes; a success naturally ending early does not authorize cutting another episode or silently buying extra retries. Count an old source episode or teacher-training prefix once.

This asks whether changing policies supply useful evidence beyond repeated stochastic attempts. A stationary actor can fail then succeed without learning. A changing actor can change without improving. Existing persistent source histories span cases; K4 case boundaries are not automatically recurrent-trial resets. State/population changes, policy noise and optimizer updates remain distinct explanations. This option alone does not show that a student exploits the resulting signal.

**C — Frozen student use of the signal.** Use a prospectively selected source-only bank/fit endpoint, with matched full and separately trained static architecture/data/optimizer controls. On fresh source cases, compare the frozen full controller with the **same weights reset** across support/query, trained static, and a declared reward-input lesion; also record the first/no-support query. Each support is a real complete episode followed by a separate fresh-reset query, with fixed controller and motor parameters and zero query SGD. Pair actual query cases/RNG. Compare actual total interaction cost, including an equal-cost no-support/retry control with its aggregation fixed in advance; do not choose a best query after observing outcomes.

A repeatable full-versus-same-weight-reset difference would show utility of retained history under that intervention. Static matches architecture/capacity, while first-query and equal-cost controls prevent paying for unsupported adaptation claims. Reward masking can reveal input sensitivity but also changes input distribution; support observations can identify a case without reward-based RL. Neither a recovery sequence, NLL gain, policy identification nor a single lesion establishes reward-driven ICRL. Success/steps/cost on actual robot queries remain the readout. No target44, screen, task57 DEV or90/Plus/Pro trajectory may enter source pretraining or these source assessments.

## Cost estimator, with no adopted numbers

Let T=40, C be fresh cases per goal, D_p paired draws for policy p, H_t the eventually declared episode cutoff and S_t actual settling actions. All C/D/H/S and support budgets below are unbound.

- A: E_A=T*C_A*sum_p(D_p), with policy roles native, tied warmup and initialized/final SAC in each declared same-mode comparison.
- B: E_B=sum_lineages,goals(E_learning+E_stationary-controls). A prospective complete K4 contributes4 episodes per case/arm; no existing history is padded or reset to fabricate it.
- C: E_C=T*C_C*sum_m[D_m*(K_m+1)], where K_m real supports precede each separate query and K_m=0 for first-query controls. Controls have their own actual costs.

Planning action bound: sum_e(H_t(e)+S_t(e)) + qualification/reset overhead + failed/retry/unresolved-intent ceilings. Actual charge uses returned primitive+settling actions plus conservative unresolved reservations, without double-counting them after resolution. Include inherited teacher-learning cost once, every assessment support/query/control and failed setup/reset; data shared by multiple fits is not recollected or multiplied. Offline fits/label inference have their own compute bill even when they add zero robot actions.

GPU estimate is sum_allocations[GPU_count * all-in charged worker time], including setup, compilation, training/labeling/inference, I/O, idle, failures and teardown. Nested child timings overlap rather than add to their parent. Obtain per-episode/update/label timing from the chosen qualified runtime before binding a numerical ceiling; no throughput or GPU availability is assumed here. CPU-worker seconds and storage are separate. These formulas are **estimates for a later review, not grants, reservations or an ETA**; all actual ceilings remain null.

## Dependencies and legacy preservation

Concrete dependencies are the official40-task frozen OpenPI motor(ec064 receipt/C565 parameters), the existing ordinary-SAC recipe and full recoveries, actual current/next raw observations/actions/noises/rewards/boundaries, post-settle state and RNG identity, and an ALL40 prospective inventory. Student comparisons additionally need the shared frozen4104D/32D interface, whole-lineage train/validation separation, TRAIN-only normalization, a fixed fit budget and same preselected TRAIN label actor for TRAIN and VAL DPT queries. AD behavior evidence and empirical improvement assessment are separate from DPT same-mode competence; none is an easy-task filter.

V2 compact evidence is currently **fresh-original-contract opt-in**, or exact same-contract resume. It cannot be turned on retroactively for the old e93 persistent continuation, reconstruct missing historical identities or automatically admit its legacy bank. Preserve all old raw data, teachers, replay, optimizer/RNG state, datasets and recoveries. Existing archived actors can be assessed without upgrading old history eligibility. Any later prospective suffix/migration decision must explicitly preserve inherited state/costs and obtain its own source admission; it is not supplied by this proposal. No silent cold restart or deletion is proposed.

The actual old25h commands continue38 **legacy** streams, retain two quota-filled CF49 roots and import the fixed8 VAL streams. They use the existing top-up/1M quota and legacy capture; their old VAL DPT labels come from independently trained VAL actors. The existing457,851-action resource charge is retained once. Funding those commands would not produce V2 evidence or same-TRAIN-teacher VAL labels. There is a hard planning choice: genuinely new original lineages/derived generation, or a separately reviewed honest boundary/suffix protocol preserving the old learner/replay/RNG and labeling the old prefix as legacy. The present V2 flag does not implement the latter. Neither choice permits cold-relaunching filled roots, refilling old task caps, manufacturing earlier actor/RNG identities or relabeling old publications in place. Same-TRAIN-teacher labeling/qualification for a new DPT generation must be bound explicitly; preserve the old VAL identities and metrics. Both choices remain unadopted, and the old proposal/ledger is unchanged.

Choose among A(teacher utility), B(history content beyond retries), or C(student use) only in a later adopted plan. They are alternatives addressing different unknowns, not additional mandatory gates. No implementation or resource work accompanies this document.
