# K/V and velocity evaluation leakage audit

Reviewed 2026-11-09, Asia/Shanghai. Scope: the completed frozen-expert AD K/V
and velocity readouts in `robocasa-three-task-kv-velocity-meta-20261105-r1`,
their SFT anchors, and the later reset-diagnostic repair. This is a code and
CPU qualification audit; it does not repeat the robot evaluations.

**No future-outcome, target-action, or cross-case history leak was identified
in the reviewed live rollout path.** The completed runs still do not establish
an in-context adaptation benefit. An earlier offline reset-diagnostic leak was
real, but used a different path and is already repaired.

## Qualifications that matter

1. **The feedback is simulator-supervised.** The rollout explicitly converts
   simulator first success into a reward after execution. This is legitimate
   past interaction feedback under this experiment's contract. These readouts
   do not establish operation with Flora-only or real-robot reward feedback.

2. **The earlier reset leak was in the offline steering diagnostic.** Its
   episode-mode context cleared recurrent memory but retained boundary-token
   action/reward/done. The current `episode_reset_batch` clears those fields.
   The live `FrozenHistoryController` already cleared them at the evaluated
   commit. See the [prior review](../steering-fit-review-20261106-r1/README.md)
   and `flow_bridge_train.py:135–148`. The later corrected-refit dispatcher
   also requires a candidate-bound gate result before invoking readout.

3. **The controls admit small initial RGB differences.** Main readout passes
   `maximum_rgb_delta=2`; physical/public states must match, but initial policy
   images need not be identical. First-query full/reset counts already differ
   on some tasks before cross-episode history exists. This is an evaluation
   precision limitation, not evidence of information leakage. Future mechanism
   claims need an identical-input first-query check or a measured repeatability
   baseline, plus paired outcome uncertainty.

4. **Each episode gets a different prospective noise draw.**
   `attempt_noise` hashes case, attempt and chunk. Draws are common across
   methods for a given query, but differ between query indices. A memoryless
   SFT policy can therefore rise or fall across the six points. Ever-success
   also increases simply through repeated attempts. Neither effect proves
   learning from history.

5. **The stopping-rule defect is separate from leakage.** A later review
   found that these Stage 1 fits stopped prematurely. The plotted readouts
   remain results of those exact checkpoints; the repaired rule has no
   completed replacement robot readout in the inspected records.

This audit did not stage back and re-audit all archived trajectories, establish
absence of overlap with the original VLA's pretraining, or prove physical-scene
disjointness between every source collection and the final case bank. No such
stronger claim follows from the passing CPU tests or stream-ID check.

## What the completed results support

After five complete preceding episodes, the descriptive equal-task means are:

| Policy/control | Query success |
| --- | ---: |
| Original SFT | 45.6% |
| K/V AD, full history | 45.6% |
| K/V AD, episode reset | 46.4% |
| Velocity AD, full history | 50.4% |
| Velocity AD, episode reset | 50.4% |

Velocity's SFT advantage can reflect the fitted steering policy. Its mean
does not increase relative to resetting that same policy. The in-context
learning thesis requires a reproducible benefit caused by retained experience,
preferably on held-out cases/tasks, with feedback/history interventions and
appropriate static/reset training controls. Per-query success need not increase
monotonically, but a higher later point alone is insufficient.
