# Does mapping the visible target arm to the source arm’s colours improve a frozen controller?

The experiment uses a Franka Panda as the reference appearance and a Kinova Gen3 (Kinova3) as a held-out physical arm model in LIBERO-Pro2.0 simulation. The stock arms have distinct meshes, joint geometry and dynamics. They share the Panda two-finger gripper, a fixed external camera, a native hand-mounted camera and world-frame OSC actions. The archived cross-arm reset restores the published Panda object layout, matches the target tool pose through IK and verifies object/fixture alignment after settling. There are no physical-hardware measurements here. [Arm contract](../libero-crossarm-20261120-r1/SIM.md)

A frozen Panda-trained policy could mistake the target arm’s visual appearance for a change in the scene. Our diagnostic projects a source material descriptor into the target camera observations on each rendered frame. It estimates the area-weighted mean RGB of visible-mesh materials on each source link from the compiled Panda model. On Kinova3 the same proximodistal index selects the source colour. Geometry, occlusions and lighting follow the native Kinova3 simulator. The target model’s visual geom membership and link ordering are privileged inputs. There is no learned network, target fitting, support rollout, target action label or paired RGB supervision. Existing observations supply both camera streams at every policy call. The reference and target provide matching reset frames, but do not provide demonstration pairs along entire tasks. A source-only palette keyed by link order remains defined when trajectories diverge.

**Falsifiable contrast.** If coarse, part-specific appearance matters to the frozen motor, linkwise reconstruction should gain native completions over the whole-arm uniform Panda colour and the unmodified target. Uniform and linkwise have access to the same source model, target link IDs, cameras and zero target support interactions. The uniform control pools the eight source colours by mesh area. Both erase the original target mesh textures and apply opaque per-geom colours using the same renderer. A gain only against raw would establish that recolouring changes outcomes; it would leave the value of the link representation unresolved. If neither improves over raw, these changes in source albedo did not solve the tested failures. Different silhouettes, arm self-occlusion, tool visibility and actual contact dynamics would remain plausible.

## Relation to prior work

Mirage cross-paints the segmented target arm with a kinematically aligned rendering of the source robot and adapts control offsets at deployment. Recolouring tests a strict subset of what changing a robot’s appearance could accomplish. It cannot establish novelty for robot-conditioned rendering. RoVi-Aug instead varies robot and viewpoint in demonstrations used to train a policy. This diagnostic freezes the motor throughout. [Mirage](https://robot-mirage.github.io/) · [RoVi-Aug](https://rovi-aug.github.io/)

Prior repository work transferred action/observation-interface yaw, scale and gripper shifts across actual arms and found a grayscale-flow reader could outperform a learned raw-RGB reader. Those arms used additional synthetic command distortions. The present intervention uses the unshifted native target interface and changes the motor’s rendered observation only. A separate historical Sawyer motor failed after hand contact on 30 of 50 development starts. Actual interaction physics is therefore a concrete competing explanation, though those were another policy, task and body.
