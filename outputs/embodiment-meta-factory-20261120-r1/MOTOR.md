## Two hypotheses and the cheapest paired test

1. **Motor headroom.** Given the true source body, a correction within the reader’s action interface rescues Sawyer failures while preserving Panda successes. A matched oracle that cannot clear the native success gate below ends this reader experiment on this checkpoint.
2. **Value of identifying the body.** Knowing which correction to use beats both a single source-selected correction and analytic system identification (SysID). If either inexpensive controller matches the oracle, use that controller. This comparison precedes any claim that public history can recover the oracle’s choice.

**Proposed protocol.** Freeze the original R2 checkpoint above, its normalization, two cameras, eight wrist/jaw values, prompt, batch shape eight, five controls per replan and 300-control horizon. For each seven-axis proposal `a`, issue `clip(a + aW + b, −1, 1)` with a full 7×7 matrix and seven biases, including the jaw. Hold the coefficients fixed throughout each query. True body identity may select coefficients once. Object poses, teacher actions, contact state and query rewards cannot reach the controller during execution. | Matched privileged oracle and best fixed correction | Execute the four fixed branches on both source bodies. On separate selection layouts, the oracle chooses the best of these four per true body. The best fixed controller chooses one map for both bodies by total native successes. Resolve ties in the order raw, Panda, Sawyer, pooled. Both selections can run directly on fresh layouts. Two body codes feeding the existing affine head suffice to express the oracle. |
| Best realizable rescue on each start | From actual paired rollouts take the maximum binary reward over the four fixed branches and SysID on each start. This is the exact hindsight ceiling for selecting **among those executed branches**. Report it separately from the source-selected controllers. Its per-start winner uses future outcomes. |

**Pass or stop.** On the twelve decision layouts per arm, require at least three net Sawyer rescues versus raw and zero spoiled Panda raw successes for H1. Score each distinct branch once and derive both locked selectors and the ceiling from those outcomes. Advance to a public-reader pilot only if H1 passes and the oracle gains at least two net Sawyer successes over **each** of SysID and best fixed, preserving every Panda success of either comparator. Otherwise stop reader work on this motor. A flat finite-bank ceiling points back to motor or interface design. A high ceiling with a weak oracle points to variation across starts or poor source map selection. Contact-phase errors and off-expert states can defeat a single fitted affine map. This screen cannot rule out every affine fit or establish population noninferiority.
