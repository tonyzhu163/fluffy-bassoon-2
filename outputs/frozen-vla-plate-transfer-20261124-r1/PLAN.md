# Does multi-arm supervision improve a frozen π₀.₅ plate-pushing policy on a third robot?

The previous adapter-only fit rescued one Kinova3 moka-pot start and lost the same layout on Panda. All source demonstrations in that fit came from Panda. This experiment varies the training arm within a single task and holds the architecture, physical source layouts, total windows, update budget and teacher family fixed. A mixed-source win against stock followed by a win against the Panda-only fit supports a benefit of source diversity for this task. A loss, a tie, or an unresolved comparison has a different interpretation. ## Training and evaluation

Use the existing 52→16→320 execution-history adapter with the original π₀.₅ weights frozen throughout training and deployment. Compare two source-only fits on the same plate-pushing layouts with matched target-action counts and training schedule. Train one with Panda data. Train the other with equal Panda and Sawyer contributions at every layout. Lock both fits, the stock model, normalization and all evaluation code before scoring. The test robot is Kinova3. On every independently sampled placement, run stock, Panda-only and mixed to the official native reward or horizon with the same reset and inference noise. Test time permits a causal observation buffer and zero optimizer steps. Record the released task identity and sampler; fresh native placements require a separate label from the published fixed-start benchmark.

## Confirmatory sequence

The first 256 independent placements have three planned looks at 64, 128 and 256. The primary is mixed minus stock native success, two-sided. The secondary is mixed minus Panda-only, tested in a fixed sequence after a positive primary. A method claim about multi-arm supervision requires both contrasts to be positive. Use one paired binary observation per distinct physical placement and preserve every discordant pair. Report rescues, losses, success-rate differences, sequentially valid uncertainty and all denominators.

**Extension registered before any target outcomes.** Continue at 512, 1,024, 2,048 and subsequent doubled looks if needed and within the 50 GPU-hour incremental campaign envelope. Per-look two-sided exact McNemar error spending is 0.005, 0.010, 0.010, 0.010, 0.0075 and then 0.0075 / 2, 0.0075 / 4, and so on. The full sum is 0.05 per hypothesis. A fixed-sequence rejection of the primary gates attribution testing. Preserve any crossing and direction at the first crossing. If a significant primary benefit is followed by an unresolved secondary, continue for the secondary. If significant harm is found, record it and stop that comparison. The registered fits, sample-generating law and noise law stay fixed across looks. A break in pairing requires a documented outcome-blind recovery. Concurrent or failed jobs, repeats on the same layout, and earlier exploratory runs do not supply new independent observations. Stop at the last completed look the resource budget permits if endpoints remain unresolved. Any later model change requires independent testing and separate error accounting.

The budget includes source collection, training, runtime qualification and all evaluation allocations. Measure the first cohort's GPU time and use it to size subsequent allocations. Report clock, cluster, job IDs, completed native cases, gross or measured GPU-hours as available, plus the decision. The primary estimand concerns one generator, task, target arm and checkpoint. Inference across tasks or real robots requires other data.
