# Outcome-blind native reset pairing fallback

This is a secondary operating rule for the 280 pre-enrolled wrist-versus-translation pairs in [the registration](../../PLAN.md). The parent owns admission. Use this recovery only when ordinary strict continuation remains unresolved for an explicitly listed batch. Preserve every published batch. The fallback produces the same two native arms and the original per-start success and unsafe measures. It changes how a common opening is obtained.

## Selection

Keep the original four ordered lanes, `rot_z/90`, scene seed 0, rep 0, release noise keys, cadence and seed-41 support assignments. Collect one original 15-control calibration per started batch and share its frozen estimates across draws and arms. Reset two separate fresh four-worker pools using the original forkserver preloading and native constructor. Hold the two pools alive. Make no scored policy query or control during selection. The native reset itself includes the registered ten settle controls. This fallback implements the original lifecycle only. A transport or constructor change needs its own native qualification and prior selection decision.

For each draw, save a frozen snapshot of each arm's raw observations, native full-state RPC leaves, initial robot state, native horizon, actual descriptions, case keys, scene and chunk seeds, full mapped observation arrays and two independently generated native query-zero noise tensors. Compare shape, dtype, keys and bytes. The native noise tensors used by inference and replay are the very tensors checked at admission. The original policy preprocessing runs downstream from these full mapped inputs. Store both typed per-leaf hash maps, actual PIDs and the decision before starting either native loop. Each loop consumes its own held reset reply once. One native proposal is computed and recorded by the original translation opening code. The original wrist opening code validates and replays it. Native action issue, replans, termination, safety and whole-batch validation remain pinned. A tape readback additionally checks the admitted leaves against the native opening archive.

Accept the first identical live pair immediately. Historical left-arm images have no role in admission. The only mismatch eligible for a redraw is one RGB pixel, by at most one count per channel, in one lane's native wrist image and its byte-identical mapped copy. This is the observed diagnostic support, not an acceptance tolerance. Any other leaf, shape, dtype, state, metadata or broader image discrepancy causes a structural halt. Compare every non-wrist leaf across draws as well. The first draw provides a same-session physical baseline. Save both complete leaf digests, a bounded pixel diagnostic and the rejection before closing either pool. Keep the rejected draws and their teardown receipts.

Draw two fresh pools after a rejection. Retaining a previous left candidate while resampling the right would change the sampling law and could favor rare retained exposures. Retaining apparently unaffected lanes would change the native four-lane lifecycle and the joint selection event. Neither reuse is equivalent on existing evidence. Report any native internal reset retry and halt, even when its eventual reset returns. Native timing and launch receipts are part of the selection evidence.

## Resource cap and sparse resume

After ordinary continuation and the drain release the original `scored/active.lock`, the parent identifies the still-enrolled batch IDs, then sets the remaining wall and remaining one-card seconds after prior charges. This fallback holds that same exclusive lock through admission, scoring and teardown. The first parent launch locks the selection file byte-for-byte and reserves the full scheduler allocation even if it exits early. Use the same file and operational pin for a sparse resume. The immutable selection has these keys.

| Key | Meaning |
| --- | --- |
| `batches` | Explicit ascending list of enrolled batch IDs in 54–69. |
| `remaining_wall_seconds`, `remaining_gpu_seconds` | Ceilings on remaining elapsed allocation time and exclusive GPU-seconds. |
| `startup_and_scheduler_seconds` | Reserve for startup and scheduler overhead, including timeout teardown. |
| `score_seconds_per_batch` | Reserve per assigned batch for the unchanged calibration, scoring and native validation. Size from elapsed producer timings and applicable policy load costs. |
| `pair_seconds` | Time allowance for a two-pool reset, state and observation receipt, noise, diagnostics and teardown. Size from measured reset-side timings and overhead, independently of match frequency. |
| `ordinary_continuation`, `budget_evidence` | Parent's pre-score evidence for the unresolved scope and the numeric cost assumptions. |

For N assigned groups and B the minimum of the wall and one-card ceilings, the cap on fresh two-pool draws per group is floor((B − startup reserve − N × scoring reserve) / (N × pair allowance)). The code requires at least one draw worth of budget and checks the payload deadline before each new draw while reserving baseline scoring for pending groups. The first accepted draw's physical reset also enters the normal arm ledgers. The conservative budget reserves that reset in the extra allowance too. Exact matches are taken on return, within the hard launcher wall. An interrupted in-flight pair remains quarantined. Set scheduler wall at or below the declared allocation and give the payload enough headroom to exit before that wall.

Sealed directory names are authoritative. A previous fallback partial directory consumes that batch's admission regardless of how far it got. An accepted pair that cannot be finished on those workers stays quarantined. Resume unstarted eligible groups only; a structural halt requires parent review before further use. Exit 3 signals incomplete assigned work. Preserve both the count of quarantined starts and the count of budget-deferred starts. Count all 280 enrolled starts in coverage even when some have no validated pair.

The normal support and arm journals contain the accepted physical resets and controls. `drawNNN/` contains rejected reset journals and separate reset receive, full-state receive, pool startup, mapping/noise and teardown timing. A complete rejected draw costs eight explicit task resets and 80 native settle controls, plus constructor work; it has zero scored proposals or actions. Use begin/end journals for interrupted work and count any marked internal reset retries separately. The original full summary scans top-level journals, so add the nested rejected draw journals to the operational cost report. Launcher elapsed seconds charge the whole GPU allocation regardless of where time was spent.

## Interpretation

The wrist-minus-translation effect is measured at a common accepted opening with shared calibration. It is conditional on the first exact-pair rule and the fixed start panel. Matching can change the renderer microstate mixture even when draws are stationary and independent. If a microstate has single-reset probability p, an independent pair weights it by p squared before normalization. Pool contention, timing, sensor history and latent state can make draws dependent, for which that weighting is only illustrative. The observed one-pixel difference reaches the policy input and can matter if it changes proposals or if intervention effects differ by microstate. If retry count, cap exhaustion, native errors or matching covary with task, calibration, renderer state or latent dynamics, recovery can be informative even though it is outcome-blind.

Report acceptance depth and both arm hash distributions by enrolled batch, strict-versus-recovered coverage, quarantines and native errors, and operational costs before interpreting outcomes. If used, label the combined full-panel estimate as a mixture of the original and recovered opening protocols. The original paired and support-cluster intervals condition on observed openings and cover neither selection bias nor missing outcomes. For an unresolved full panel, report coverage and optionally the descriptive fixed-panel identification interval `[(S−m)/280, (S+m)/280]` for each binary paired contrast, where S is the sum of verified paired differences and m is the number of unvalidated starts. If all pairs seal, an assumption-free sensitivity to assigning different renderer realizations to k recovered starts is at most `2k/280` in the paired difference. This bound is separate from sampling uncertainty.

## Preparation

Linux qualification uses one CPU, software EGL, native releases and the real batch054 reset RPCs. At query zero an inert policy calls the released seeded noise method and emits a dummy proposal; both runs stop before controller dispatch. Fixtures exercise rejection, physical and external-camera faults, cross-draw drift, exact replay, cap exhaustion, sparse resume and the scoring lock. The fixture calibration is fixed for wiring. The real calibration, policy and simulator action code are invoked only by the parent-owned launcher.
