# Does finger friction change which frozen bottle-placement program succeeds?

Use one archived research pose, LIBERO Goal 2 (wine bottle to cabinet), reset 24, seed 18180124. Goal 2 is in the campaign training-task pool. This is a custom physics experiment on an already studied pose. Use no official evaluation protocol, held-out task, model inference or fitting. Stop after this pose yields its six-cell native outcome table, or at a technical blocker. Single Linux development CPU process, Mesa software rendering, 0 GPU-hours, 15-minute preferred wall budget.

The [command-grasp result](../libero-command-grasp-20261119-r1/RESULT.md) found a two-pose dependence on regrasp under released D17, which changes the gripper command. The [temporal recovery study](../libero-temporal-recovery-20261119-r1/RESULT.md) found that the cabinet regrasp and transport alternatives can recover different released faults. We select the first pose in that study, 24, where regrasp succeeded on D17 and a transport tape succeeded on D18. The independent nominal query succeeded on ordinary physics. No friction outcomes informed the selection.

Run fresh BASE simulator resets for each program and material. After the standard settle and before the first issued command, leave the ordinary compiled model intact or set sliding friction to 0.05 on the two finger collision meshes and their two pads. Change no object, priority, solver, force or action parameter. MuJoCo combines the surface coefficients. Report realized coefficients for the same finger and bottle geom pair instead of assuming the solver uses 0.05. This models a material change for the controlled episode, after common settling.

- Replay the 300 issued actions of the independent ordinary π0.5 query from closed01.
- Apply the published D17 retreat/return controller to that tape, using its original timing and public wrist state. Both conditions receive the same feedback rule.
- Replay the 300 logged actions from π0.5 originally replanning under D18 in release02. The D18 event is absent here. This is a pose-specific optimistic alternative.

Gate 0 requires native nominal default reproduction, identical reset physics, matched actions before first finger contact, and equality of both 256-pixel camera images and all public proprioceptive arrays from reset through the last complete precontact control in each pair. Compare native reward/success/termination in that prefix. Log finger contacts at every MuJoCo integration step. To call the material intervention physically effective, require a changed realized sliding coefficient on a common finger/bottle geom pair and a bottle trajectory displacement exceeding 1 mm between the fixed default branches. Distinguish trajectory evidence from task success.

Gate 1 asks whether an oracle choosing a whole program by material at reset gets more native first hits than the best single fixed program. Also report both any-time and final native success, first hit, native reward, bilateral grasp duration and maximum bottle lift. Continue to control 300 as in the archive to check persistence after first success. A fixed program succeeding under both materials, an unreachable material, or all outcomes tying rules out a strict oracle advantage on this pose and menu. One pose cannot establish generalization, online identifiability or necessity of history. No tuning or further poses after the table.
