# Frozen π0.5 distillation from three RoboCasa365 PPO teachers

The two students fit the same 1,728 action chunks from 144 training reset scenes. Each task contributes 48 training and 16 validation resets. Every reset pairs one full pre-PPO SFT support trajectory with one full final-PPO query trajectory. Native physical and public initial states match, all 600 controls executed, and the split keeps each seed and simulator scene XML within one partition. This pilot uses the original 64-case source banks per task. The published 512-case evaluation used separate banks.

The query input is the released three-camera, public-state, instruction interface. The label is the executed 50-by-12 physical PPO action chunk saved with that pre-action observation. Keep successful and failed episodes. Only the history-conditioned student sees the prior SFT episode, including its public camera summaries, proprioception, physical controls, native rewards and boundaries. Both students use independent rank-eight query/value LoRA weights in the last four native action-expert blocks. The DPT student also uses a learned GRU and a projection into native action tokens. Original π0.5 weights are frozen. Require exact zero-adapter parity and nonzero gradients on the actual GPU.

Train one fit per arm for two epochs with the same task-balanced batches of six, initialization of the shared adapter design, flow noise and time samples. Save optimizer, adapter and RNG state. Evaluate the fixed final models on all 576 held-out query chunks using shared draws. Compare the frozen policy, memoryless adapter, DPT with matching support and that same DPT model with another held-out support of the same task. Report by task. The independent experimental unit is the reset scene. Native rollout success on fresh cases is a separate evaluation. A single fit per arm and a repeated initial pose limit generalization claims. No new online PPO or GRPO data are required for this pilot.
