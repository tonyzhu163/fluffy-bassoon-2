# Can a physical probe recover native task success under a change of command coordinates?

Use the same sixteen BASE development query resets and archived open-loop controls from the frozen π0.5 [menu02 run](../libero-decision-pretraining-20261119-r1/RESULT.md), including the query whose old support lacked a Y probe. In a fresh support reset issue two short physical pulses along X and Y. Apply one hidden wire-coordinate convention for both support and query. Read the wire commands and actual measured motion; the estimator receives neither the simulator's convention nor the query outcome. Use fixed pulse order, duration and balanced directions across resets. This creates physical support observations that were absent from the fitting data.

Evaluate nominal, reversed X, reversed Y and reversed XY. Compare the preregistered seed-41 shared learner with the analytic rule, the fixed identity decoder, opposite-convention support, and the true convention. For each identical query start and saved π0.5 command tape, run the four possible net XY sign transforms through native physics. A fixed estimate and the true actuator convention determine a unique net transform, so all arm scores can be read from these measured branches. Use native rewards and success within the original tape budget. Record actual physics start and trace agreement with the nominal archive. This tests whether corrected commands can change native success without the expense of running identical physical branches multiple times.

This is our constructed coordinate task on released BASE environments. The nominal tapes stay open-loop during replay. Strong analytic results and weak learner results would localize the failure to generalization from archived to physically elicited probes. Agreement with the analytic oracle would close this two-axis test and move the research decision to a released perturbation. This pilot cannot establish that pretrained VLA weights contain a meta-learning algorithm.

Predeclare a zero-GPU CPU native development panel of 64 short supports and 64 query branches, one worker and a 30-minute wall cap. Preserve each branch's native reward, duration, assigned case and physical transform. The official transfer tasks stay sealed.
