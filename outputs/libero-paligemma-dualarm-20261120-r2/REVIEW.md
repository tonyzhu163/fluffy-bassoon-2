# Independent validity review of the Goal 5 dual-arm run

**The reported 45 camera Panda demonstrations cover 14 layouts. Six initial Sawyer camera positives establish that a Sawyer teacher can succeed. Neither count establishes eligibility for the dual-arm fit or success of the learned motor.** The first decision is whether the frozen bank contains enough distinct successful **training** layouts and any **offline validation** labels on each arm. The larger banks were still running. I reviewed the local sources, the released Goal 5 start table and the pinned Panda demonstration archive. The R2 bank indices, camera tapes and fit reports were unavailable locally, so the reported counts and actual renderer mix are operator observations.

## Findings that affect execution or interpretation

1. **High · Production fitting can silently consume software-rendered smoke demonstrations.** The GPU launcher checks the allocated device and exports the Baige flag. The simulator checks for NVIDIA only under that flag. The CPU launcher selects Mesa and then accepts an arbitrary entry point with arguments, including a camera collector. The FIT loader checks arm, release, task, seed and tape dimensions, but never checks or retains the reset's renderer. Two valid-shaped banks rendered on different backends can enter both motor SFT and adapter fitting. If backend tracks arm or split, visual differences can become an unintended predictor. Require the recorded NVIDIA vendor and a nonempty renderer for every production camera row at ingestion, retain them and the collector attempt/probe identity in the manifest, and restrict the CPU launcher to diagnostic modes. Camera-free search can still supply candidate commands for a fresh successful GPU replay. Existing rollouts need a receipt inventory before claiming any contamination. 6. **Medium · Pixel scaling is consistent, but camera orientation is implicit.** Both cameras pass through the same uint8 → [0,1] → antialiased bicubic 224 → [−1,1] path for SFT and live inference, external view first. The released observation normalizer only casts and makes arrays contiguous. Stock robosuite 1.4.0 defaults to OpenGL rows, and the LIBERO video writer reverses the row axis for display. R2 never records the effective convention or applies a view transform. Consistent raw orientation across fit and inference preserves causal alignment. A pretrained vision tower can nevertheless see unfamiliar upside-down scenes, and differently configured collectors could disagree without a shape error. Record the effective convention, compare an asymmetric feature in both raw views to the display-oriented reference, and use one shared transform if a correction is warranted. Changing it requires a fresh fit. ## Controls and evidence

- **Image/action alignment.** The Panda replay and Sawyer collector append the current observation before stepping the command. The tape writer stacks those frames and issued commands in identical order. The motor pairs frame and state at index `t` with controls starting at `t` and masks the final short chunk. Adapter proposal caching advances by five controls and retains the terminal partial chunk. Source and target live episodes check termination after every control and replan from the last post-action observation. No extra shift belongs in this live tape path. A direct integrity check for imported banks is to compare fresh reset images and first-step images against tape frames 0 and 1 for a known pose/seed. ## Operator follow-through

The first production fit recorded four training banks from distributed NVIDIA jobs. Both sources supplied distinct training layouts and all four offline layouts. The first offline sample included per-layout parameter search for the teacher. Subsequent frozen bank comparisons keep offline sweep episodes only when the first prespecified candidate succeeded. Rechecking the renderer at ingestion and requiring complete native endpoints are implemented in the expanded fit. The same raw image convention is used during native capture and evaluation.
