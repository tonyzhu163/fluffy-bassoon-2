## What the paired check measures

Fix the ordered support poses, prompts, intended command tapes, query reset, query noise and available actions. For each practice, reduce each of the two native predicates with “ever true in controls 1–300.” Keep a side if both rewards are zero, exactly one hidden goal is compatible with these two bits given the actual practice hits, and exactly one query instruction can earn that goal. A group qualifies when both hidden goals have such a side and the successful query instruction switches. The reader sees only factual public history and the two reward bits. Query outcomes and both practice predicate vectors are evaluator data. ## What can be read from a tape

- The bottle live collector uses both cameras for the motor, then saves 300 × 7 intended actions, 300 × 9 measured states (wrist XYZ, XYZW quaternion and two jaw positions), 300 × 2 native hits, contact and relative object height. Event information, reset identity, mode, pose and seed appear in sidecars. RGB is absent from the saved live tapes. The custom replay writer saves only intended actions, states and hits, with cameras disabled. D18’s saved-command scorer computes motion features in memory and writes aggregate scores and event outcomes. Its script has no per-control tape writer. ## Falsification and new starts

1. **Rescore the five custom pairs first.** Freeze the existing bowl-only jaw-widening rule and six-feature nearest-neighbor completion reader. The latter uses commanded closure to measure jaw widening and width, plus wrist vertical and horizontal travel. Apply each policy to each side independently and record its two destination choices before joining query outcomes. Use a source-fixed tie rule for exact complete-pair counts, with expected ties reported separately. Also score rewards/order alone, intended commands plus rewards, and the same reader with the opposite side’s public sensor histories under factual rewards. On these fixed tapes, that swap preserves the commands and reverses the informative execution. Exclude executed overrides, contact, height, predicates, trigger time, filenames and identifiers from all reader features. Report both-sides-correct pairs, side successes, individual choices and distinct query starts. Also retain all assigned histories in a separate native-success denominator. 3. **Give both readers the same physical evidence and query menu.** Replay the same nominal support commands in sham and event branches. Verify all 300 intended commands and the pre-event physical prefix. Save synchronized external/wrist RGB, intended commands and proprioception from both branches at a fixed cadence. For a claim about changing cadence, measure both five- and ten-control queries per destination from each common reset and query draw, and repeat the bowl four-action qualification.
4. **Decision.** If the frozen nonvisual reader selects the sole successful action on both sides of every eligible new pair, it reaches the attainable strict-pair ceiling without a robot-pretrained visual reader on this panel. A reproduced individual pair already falsifies visual necessity for that instance. Count visual-only and nonvisual-only paired successes explicitly. Zero eligible pairs leave the comparison uninformative. A visual advantage over nonvisual readers would still require a matched generic or randomly initialized visual encoder comparison to attribute the advantage to robot pretraining. The motor itself remains the same pretrained policy in every arm.
