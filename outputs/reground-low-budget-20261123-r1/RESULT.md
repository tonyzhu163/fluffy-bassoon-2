# ReGround rotation at 15, 100 and 1,000 target transitions

**The released rotation forward model and IDM can fit at all three budgets.** On seed 0 the unmodified upstream fit at 15 completed with six transitions in training and nine in validation. Its forward and inverse models stopped after 20 and 17 epochs. Omitting the post-fit diagnostic on 1,880 additional target transitions produced bit-identical values for all 18 forward and 14 IDM parameter/normalizer tensors, identical internal validation metrics and the same stopping epochs. The remaining open question is task success and unsafe incidence under native rollouts. This CPU study scored zero benchmark episodes and submitted zero jobs. ## What enters the models

The source is the archived `rot_z/90` target collection for each original adaptation seed. We verified SHA-256 against all 375 target shards, all 20 historical model files and their specs and fit metrics. The source audit read **1,118,740 distinct archived target transitions** across five seeds. Each seed has 119,460 policy-driven transitions and respectively 104,058 / 104,381 / 104,175 / 104,131 / 104,695 babbling transitions. The five held-out VLA episodes contain **1,880** transitions per seed. Nominal forward and inverse weights come from that seed’s original 100,000-transition fit, shared across all budgets. The original nominal on-policy diagnostics read a further 616 / 863 / 622 / 1,103 / 854 nominal transitions by seed, with zero additional nominal transition reads when reusing the caches. New target weights start from the original model’s saved pre-construction CPU RNG state for that seed and kind. No target weights are transferred from the 10k fit. The experiment inherits the authors’ validation-selected rotation configuration and model specifications. [Historical fit receipts](../reground-rotation-reference-20261123-r1/evidence/fitted-models.json) · [Preparation script](prepare.py)

For each source separately, sort shard filenames, interleave episodes round-robin by within-shard episode index, and exclude the final five VLA episodes before taking its prefix. Take `round(0.6 × budget)` babbling transitions and the remainder from the eligible VLA pool. Truncate the final episode with its next state intact. Append the VLA episodes to the babbling episodes. Every prefix matched the released `adaptation_data` byte for byte, including 10,000. Source-specific prefixes nest exactly. The episode partition can change with prefix size. Each manifest records source/shard/episode/task, half-open transition spans, train/validation indices, each source hash, combined tensor hash, serialized tape hash and model-window counts. The tensor hash frames each episode by uint64 little-endian action count, then hashes C-order little-endian float32 X and A. At 15 and 100 the two prefixes both come from `spatial_0`, one episode per source. A seed-keyed NumPy permutation assigns the first `max(1, round(0.1 × episode_count))` episodes to validation. Both models reuse the same split. At seeds 0–2 all gradient updates use the policy-driven prefix, and early stopping uses babbling. Seeds 3–4 reverse those roles. At 1,000, seeds 0/1/3 have five prefix episodes, seeds 2/4 have six, and all have one validation episode. At 15 this protocol uses two different logged trajectories. It cannot be interpreted as adaptation during one 15-action trial.

Both target models train on one-step windows. The five-member forward ensemble has width 1,024, depth six, L=0 and unroll=1. The IDM has width 256, depth five and L=2 with left-padded no-op history. A one-step transition remains usable at an episode boundary. Validation samples must contain a window, and the training normalizer’s sample standard deviation requires at least two training transitions. All observed splits meet those constraints. Batch size 512 is sampled with replacement; the release executes at least one update per epoch. It uses AdamW, learning rate 0.003, at most 200 epochs and patience 15, restoring the best validation state. The native improvement tolerances are 1e-5 (forward) and 1e-6 (IDM). The secondary eight-step forward metric requires an eight-transition validation segment. With a six-transition validation episode it reports just one-step MSE. Neither the fit nor the launcher changes a window, batch, patience, history or optimizer setting for 15. [Model config and per-budget contracts](contracts/) · [CPU fits](evidence/cpu-fits.json)

## Exact access accounting

| Stage | Target transitions accessed |
| --- | --- |
| Source preparation and verification | Full historical pools once as **distinct** examples, with repeated reads for hashes and native equivalence. No new collection. |
| Stock upstream fitting of both target models | The same B transitions for normalization, optimization and early stopping, plus the same 1,880 disjoint VLA transitions for post-selection metrics. Unique semantic totals at B=15/100/1,000 are **1,895 / 1,980 / 2,880**. The full-budget comparator has 11,880. |
| Stock raw loader I/O | An unmodified cold fit decodes whole pools when extracting prefixes. Per model it decodes the full babble pool and the full VLA pool twice (prefix eligibility and post-fit diagnostic). For seed 0 that is 342,978 decoded transition occurrences, 223,518 distinct. The two target models repeat those reads. |
| Bounded production fit | One isolated B-transition tape per model, including validation. Both models reuse it. Unique targets B, external holdout reads zero. Across three budgets the per-seed union is 1,000. Across all five seeds the union is 5,000. |
| Deployment before the first action | Four verified model caches, frozen policy/assets, known rotation recipe, and the scored episode’s initial state and policy observation. Zero calibration-tape accesses, separate target transitions, probe controls or extra calibration resets. |
| Deployment during scoring | One continuous native episode per assignment. The controller consumes current 25-D robot state and intent/executed histories. Frozen π₀.₅ receives two camera views, proprioception and instruction. Each row records actual steps, traces, success and unsafe. Resets include ten unobserved simulator settling no-ops before the scored initial state. These are environment work, never training examples or controller observations. |

The bounded fit is an explicit change to **diagnostic data access**. It supplies the exact original prefix to `cache.fit_model` and supplies an empty external diagnostic pool only after native model selection. The internal validation split and its metrics still run. The original full collection is accessible to the preparer. The fitter reads its own tape, selected model specifications and initialization, while deployment loads the four caches with fitting disabled. The small per-cell runtime contract excludes the external holdout and full-budget outcomes. Negative controls attempted raw data, sealed tape and alternate calibration-loader access during deployment and were rejected. [Production data guards](runner.py) · [CPU access and equality checks](check_transport.py)

The native config uses a deployed one-step IDM action anchor, absolute nominal reference, CEM horizon 1, 256 candidates, four iterations, trust weight 100 and native gripper pass-through. The nominal IDM is loaded by the upstream builder; the rotation controller uses the nominal forward model and both deployed models. The monitor is off. The `max(2000, round(eps × budget))` babbling minimum applies to delay estimation for `vla_shift` and `lin_shift`; this rotation branch makes no delay or linear-anchor fit. The controller needs no simulator snapshot, object state, oracle rotation or held-out calibration trace. The simulator applies the known shift, and the selected recipe is specific to this condition. The fixed speed envelope and simulator safety predicates score outcomes. Success terminates an episode and never enters model fitting. ## Interpretation

The full-budget reference achieved **1,271/1,400** successes (IQM 0.974, released 95% interval 0.957–0.991) and **582/1,400** unsafe episodes (IQM 0.339, interval 0.296–0.390). Frozen Base succeeded on zero. The proposed paired panel uses the pre-existing controls and identical test assignments. It asks how much of that measured recovery survives each data limit. The CPU fits and finite synthetic controller actions establish that all three arms can be run. Relative validation losses across single-source splits do not answer the native success question.
