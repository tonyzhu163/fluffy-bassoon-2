## Implementation and integration

The fallback first issues the unmodified archived actions to a Panda in the parent simulator at the archived seed and row. It requires the matching BDDL and prompt, positive native reward and success at the recorded terminal control. The resulting geometry supplies the source plate trajectory, which is absent from the HDF5. The readback reports the largest wrist position and quaternion-angle differences against the post-action HDF5 observations. The source reset supplies the pre-action state for control zero. This indexing follows the earlier native BASE readback. [Replay alignment evidence](../libero-s20-motor-20261119-r1/RESULT.md) · [Implementation](oracle_fallback.py)

At the requested seed and row, a Panda with the donor's exact initial-state fingerprint can reuse the released commands. Every Sawyer uses the tracker. It measures the live grip-site XYZ, hand quaternion and plate before every control, corrects the recorded world-frame OSC increment for tracking error and holds the reference clock if the arm falls behind. The approach shifts with the initial plate displacement and tapers that shift to zero toward the demonstrated destination. Plate feedback adjusts the contact offset by up to 15 mm per horizontal axis. Both arms use the same mounted PandaGripper, so comparing the hand-link rotations preserves the gripper orientation. The 12 mm and 0.12 rad advancement tolerances and slip correction are unqualified controller settings. Per-step errors, reference indices, contacts, plate movements and commands are written with each target attempt. Source geometry is used only by the demonstrator. The learner receives the ordinary on-body tape. [Parent simulator](sim.py) · [Tape writer](demos.py)

The parent can run this as a separate collector using the pinned simulator Python and environment from DEMOS.md. Choose an unused output path and the original panel's seed base. The downloaded HDF5 is the only additional data dependency. The script accepts `--bodies Panda` for the first two target starts and `--bodies Panda Sawyer` for the paired panel. It defaults to reference group 22. Preserve the original four requested target starts, including row 1.

```sh
hf download zhouxueyang/LIBERO-Pro2.0-Train --repo-type dataset \
  --revision 6c4c5524676815a88880a7025badd17fb724f7f4 \
  data/libero_goal/task_5/BASE/episodes.hdf5 --local-dir "$data_root"
"$CROSSARM_SIM_PYTHON" -Bu "$here/oracle_fallback.py" \
  --archive "$data_root/data/libero_goal/task_5/BASE/episodes.hdf5" \
  --output "$fresh_output" --seed "$seed_base" --poses 0 1 --bodies Panda Sawyer
```

For an in-process integration, build `ref = panda_reference(archive_path, 22)` once, create `TrajectoryExpert(ref, env.expert_scene())` after each target reset and issue `expert.action(obs, scene)` with fresh inputs each control. The standalone path also preserves exact Panda replay when eligible. Accepted tapes use the parent's writer and indexed native receipts. The reference replay is a control and does not count toward the four target starts. Require native terminal success and positive reward on both rows on each source body before collecting training data. A donor failure localizes a replay/runtime mismatch. A passed donor followed by a Sawyer miss leaves transfer unqualified. Row 1 specifically tests generalization beyond an archived reset. Repeated successful use of one donor still represents one oracle trajectory when reporting source diversity.
